## 一、一句话结论

AP3216C 的匹配不是 platform 设备那一套，而是 **两层**：

```text
① 控制器：dtsi i2c@021a0000  ↔  i2c-imx（platform）→ 适配器 i2c-0
② 从设备：dts  ap3216c@1e    ↔  ap3216c（i2c_driver）→ /dev/ap3216c
```

键是 **`compatible` + `reg`**；本板总线号 **`i2c-0` = SoC I2C1**（见 `11`）。

## 二、本板 dts 字段对照

板级节点（`imx6ull-14x14-evk-gengtao0901.dts`）：

```dts
&i2c1 {
	clock-frequency = <100000>;
	pinctrl-names = "default";
	pinctrl-0 = <&pinctrl_i2c1>;
	status = "okay";

	mag3110@0e { ...; status = "disabled"; };

	ap3216c@1e {
		compatible = "LiteOn,ap3216c", "ap3216c";
		reg = <0x1e>;
	};
};
```

| dts 项 | 作用 | 谁消费 |
|--------|------|--------|
| `&i2c1` | 引用 dtsi 里 `i2c1: i2c@021a0000`，把控制器打开 | `i2c-imx` |
| `status = "okay"` | 覆盖 dtsi 默认 `disabled` | OF / 驱动 probe |
| `pinctrl-0 = <&pinctrl_i2c1>` | UART4_TX/RX → I2C1_SCL/SDA | pinctrl（控制器 probe 时） |
| `clock-frequency` | 总线 100 kHz | `i2c-imx` |
| 子节点 `ap3216c@1e` | 在该适配器下登记一个 **i2c_client** | I2C 核心 `of_i2c_register_devices` |
| `compatible` | 驱动匹配字符串（优先 OF） | `ap3216c_of_match` / `id_table` |
| `reg = <0x1e>` | 7bit 从地址 → `client->addr` | I2C 传输 |
| `mag3110` `disabled` | `for_each_available_child` **跳过** | 不创建 client、不 probe |

dtsi 中控制器骨架：

```dts
i2c1: i2c@021a0000 {
	compatible = "fsl,imx6ul-i2c", "fsl,imx21-i2c";
	reg = <0x021a0000 0x4000>;
	...
	status = "disabled";   /* 板级 &i2c1 改成 okay */
};
```

pinctrl（同文件 `iomuxc`）：

```dts
pinctrl_i2c1: i2c1grp {
	fsl,pins = <
		MX6UL_PAD_UART4_TX_DATA__I2C1_SCL 0x4001b8b0
		MX6UL_PAD_UART4_RX_DATA__I2C1_SDA 0x4001b8b0
	>;
};
```

## 三、驱动侧匹配表（出厂 `ap3216c.c`）

```c
static const struct i2c_device_id ap3216c_id[] = {
	{ "ap3216c", 0 },   /* DEVICE_NAME */
	{ }
};

static const struct of_device_id ap3216c_of_match[] = {
	{ .compatible = "LiteOn,ap3216c", },
	{ }
};

static struct i2c_driver ap3216c_driver = {
	.driver = {
		.name           = "ap3216c",
		.of_match_table = of_match_ptr(ap3216c_of_match),
	},
	.id_table = ap3216c_id,
	.probe    = ap3216c_probe,
	.remove   = ap3216c_remove,
};
module_i2c_driver(ap3216c_driver);
```

| 表 | 匹配什么 | 本板 dts 对应 |
|----|----------|----------------|
| **`of_match_table`** | `compatible` 全串 **`LiteOn,ap3216c`** | 双写里的**第一项**（OF 优先走这里） |
| **`id_table`** | `client->name == "ap3216c"` | 由 OF 从 compatible 生成 modalias；第二项 `"ap3216c"` 作兜底 |

**为何双写 `compatible`：**

1. OF 路径：必须命中 `"LiteOn,ap3216c"`（表里只有这一条）。
2. 4.1 的 `i2c_device_probe` **要求** `driver->id_table` 非空，并用 `client->name` 查 id；`of_modalias` 通常把 `LiteOn,ap3216c` 收成名字 **`ap3216c`**，与 `id_table` 一致。
3. 只写 `"ap3216c"`：OF 表可能对不上，只能靠 id 路径，脆弱。
4. 只写 `"LiteOn,ap3216c"`：多数情况下也通，但双写更稳、与出厂/文档一致。

## 四、匹配全过程（按启动顺序）

### 4.1 总览

```text
U-Boot 加载 dtb
        ↓
① platform：i2c@021a0000 匹配 i2c-imx
   → 选 pinctrl_i2c1、注册适配器 → 本板为 i2c-0
        ↓
② of_i2c_register_devices(adap)
   → 遍历 &i2c1 下 available 子节点
   → ap3216c@1e：读 reg=0x1e、compatible → 创建 i2c_client（如 0-001e）
   → mag3110@0e status=disabled → 跳过
        ↓
③ 总线匹配 i2c_device_match
   → 优先 of_driver_match_device（LiteOn,ap3216c）
   → 否则 id_table（名字 ap3216c）
        ↓
④ i2c_device_probe → ap3216c_probe
   → 写 0x00=0x04 复位 → 0x00=0x03 使能
   → misc_register → /dev/ap3216c + sysfs als/ps/ir
        ↓
⑤ 用户态：cat als；i2cdetect 见 UU
```

与屏（`09` platform+lcdif）、网（`10` platform+fec+phy）对比：**本器件第二层是 i2c_client，不是又一个 platform_device。**

函数级细节见 [§五](#五代码调用链走读地图)。

### 4.2 Step 1 — 控制器起来（I2C1 → `i2c-0`）

| 条件 | 说明 |
|------|------|
| `CONFIG_I2C` + `CONFIG_I2C_IMX` | 框架 + 控制器驱动 |
| `&i2c1 { status=okay; pinctrl-0=... }` | 节点可用 + 脚复用 |
| dtsi `compatible = "fsl,imx6ul-i2c", ...` | 匹配 `i2c-imx` |

成功信号（L0）：

```text
i2c i2c-0: IMX I2C adapter registered
/dev/i2c-0
```

`reg = <0x021a0000>` 只描述控制器 MMIO，**不是**从地址 0x1E。

### 4.3 Step 2 — 子节点变成 `i2c_client`

I2C 核心（`i2c-core.c`）在适配器注册后：

```text
of_i2c_register_devices(adap)
  for_each_available_child_of_node(adap->dev.of_node, node)
      of_i2c_register_device(adap, node)
```

对 `ap3216c@1e`：

| 属性 | 结果 |
|------|------|
| `reg` | `client->addr = 0x1e` |
| `compatible` | 填 `client` 的 OF 节点；生成 `client->name`（常见为 `ap3216c`） |
| 挂在哪个适配器下 | 决定是 `0-001e` 还是 `1-001e` |

板上核对：

```bash
find /proc/device-tree -name 'ap3216c@1e'
# .../i2c@021a0000/ap3216c@1e

ls /sys/bus/i2c/devices/
# 绑定后常见 0-001e
```

`@1e` 只是节点名习惯；**真正地址以 `reg` 为准**（二者应一致）。

### 4.4 Step 3 — `i2c_device_match`：谁绑谁

```text
i2c_device_match(dev, drv):
  1) of_driver_match_device  → 对 of_match_table（LiteOn,ap3216c）  ← 本板主路径
  2) ACPI（本板无关）
  3) i2c_match_id(id_table, client) → client->name 与 "ap3216c"
```

本板：步骤 1 即成功 → 驱动与 `0-001e` 绑定。

### 4.5 Step 4 — `ap3216c_probe`

4.1 框架侧（注意）：

```c
/* i2c_device_probe 摘要 */
if (!driver->probe || !driver->id_table)
	return -ENODEV;   /* 即使 OF 已匹配，也必须有 id_table */
driver->probe(client, i2c_match_id(driver->id_table, client));
```

驱动侧：

```text
ap3216c_probe(client, id)
  → ap3216c_init：写 SYSTEMCONFIG 0x04 / 0x03
  → misc_register → /dev/ap3216c
  → groups → sysfs ir/als/ps
```

成功时**通常无 dmesg**（见 `12`）；失败才有 `ap3216c init failed`。

判据：

```bash
ls -l /dev/ap3216c
i2cdetect -y 0    # 0x1e → UU
```

### 4.6 Step 5 — 用户态读数（匹配之后）

```text
cat /sys/devices/virtual/misc/ap3216c/als
  → show_als → i2c_transfer(client->addr=0x1e, 寄存器 0x0C/0x0D)
```

`client` 指针在 probe 里保存；此后传输走 **适配器 `i2c-0` + 地址 0x1E**。

## 五、代码调用链（走读地图）

> 对应上文「四、总览」①～⑤；内核路径以 `linux-imx6ull-kernel-code/` 为根。  
> AP3216C 源文件在 overlay：`linux-kernel-overlay/common/drivers/char/ap3216c.c`（apply 后等同 `drivers/char/ap3216c.c`）。  
> 行号随版本可能微调，**以函数名为准**。

两层绑定：

```text
platform 总线：i2c@021a0000  ↔  i2c-imx
i2c    总线：0-001e           ↔  ap3216c
```

**Initcall 顺序：** `i2c-imx` 为 `subsys_initcall`，`ap3216c` 为 `module_i2c_driver`（`device_initcall`）。通常先有 `i2c-0` / `0-001e`，再注册驱动并绑定；若驱动更早，则在 `i2c_new_device` → `device_register` 时当场 probe。

### 5.1 总调用图（对照总览 ①～⑤）

```text
① 控制器
of_platform_populate → platform_device(i2c@021a0000)
  compatible: "fsl,imx6ul-i2c","fsl,imx21-i2c"
  （本树 of_match 表无 imx6ul 项，实际命中 "fsl,imx21-i2c"）
        ↓
subsys_initcall(i2c_adap_imx_init)
  → platform_driver_register(&i2c_imx_driver)
  → drivers/base/dd.c::really_probe()
       ├─ pinctrl_bind_pins()              ← 消费 pinctrl-0=&pinctrl_i2c1
       └─ i2c_imx_probe(pdev)              drivers/i2c/busses/i2c-imx.c
            ├─ of_match_device(i2c_imx_dt_ids)
            ├─ ioremap / clk / irq
            ├─ of_property_read_u32(..., "clock-frequency")
            ├─ adapter.dev.of_node = pdev->dev.of_node
            └─ i2c_add_numbered_adapter
                 → i2c_register_adapter    drivers/i2c/i2c-core.c
                      ├─ device_register → 出现 i2c-0
                      └─ of_i2c_register_devices(adap)   ← 进入②

② 从设备
of_i2c_register_devices(adap)
  for_each_available_child_of_node(...)   // mag3110 disabled → 跳过
    └─ of_i2c_register_device(adap, node)
         ├─ of_modalias_node()             drivers/of/base.c
         │    "LiteOn,ap3216c" → 去厂商前缀 → info.type="ap3216c"
         ├─ of_get_property("reg") → info.addr=0x1e
         └─ i2c_new_device(adap, &info)
              ├─ client->name / addr / of_node
              ├─ i2c_dev_set_name → "0-001e"
              └─ device_register → 挂 i2c_bus_type  ← 可立刻进③④

③ 匹配（驱动侧，可先可后）
module_i2c_driver(ap3216c_driver)
  → i2c_add_driver → i2c_register_driver
       → driver_register → 对已有 client 再匹配

i2c_bus_type.match = i2c_device_match
  1) of_driver_match_device → LiteOn,ap3216c   ← 本板主路径
  2) ACPI（跳过）
  3) i2c_match_id(id_table) → client->name=="ap3216c"

④ probe
really_probe → i2c_device_probe
  → 要求 driver->id_table 非空（4.1）
  → ap3216c_probe(client, id)
       → ap3216c_init：写 0x00=0x04 / 0x03
            → ap3216c_write_reg → i2c_transfer → i2c_imx_xfer
       → misc_register → /dev/ap3216c + sysfs als/ps/ir

⑤ 用户态
cat .../als → show_als → ap3216c_read_als_data → i2c_transfer → i2c_imx_xfer
i2cdetect @0x1e 见 UU ← 地址已被 bound client 占用
```

### 5.2 分文件函数表（按走读顺序）

#### A. 驱动模块入口

| 顺序 | 文件 | 函数 / 符号 | 作用 |

#### B. 控制器：`i2c-imx` → 适配器 `i2c-0`

| 顺序 | 文件 | 函数 | 作用 |
|------|------|------|------|
| B1 | dtsi `i2c1: i2c@021a0000` | — | `compatible = "fsl,imx6ul-i2c", "fsl,imx21-i2c"` |
| B2 | 板级 dts `&i2c1` | — | `status=okay`、pinctrl、`clock-frequency`、子节点 |
| B3 | `i2c-imx.c` | `i2c_imx_dt_ids[]` | 有 `fsl,imx21-i2c`（靠 dts 第二项命中） |
| B4 | `i2c-imx.c` | `i2c_imx_probe` | MMIO / clk / IRQ；读 `clock-frequency` |
| B5 | 同上 | `adapter.dev.of_node = ...` | **关键**：子节点从此节点遍历 |
| B6 | 同上 | `i2c_add_numbered_adapter` | 注册适配器 |
| B7 | `i2c-core.c` | `i2c_register_adapter` | 设备名 **`i2c-0`** |

## 六、深挖：`platform_driver_register(&i2c_imx_driver)`

> 对应 §五 总调用图 **①**；本行**不是立刻操作 I2C 硬件**，而是：把 `i2c-imx` 挂到 **platform 总线**，再对**已有** platform 设备做一轮 match；命中 `i2c@021a0000` 后才进 `i2c_imx_probe`。

### 6.1 入口

```c
/* drivers/i2c/busses/i2c-imx.c */
static struct platform_driver i2c_imx_driver = {
	.probe = i2c_imx_probe,
	.remove = i2c_imx_remove,
	.driver	= {
		.name = DRIVER_NAME,
		.owner = THIS_MODULE,
		.of_match_table = i2c_imx_dt_ids,  /* 含 fsl,imx21-i2c 等 */
		.pm = IMX_I2C_PM,
	},
	.id_table	= imx_i2c_devtype,
};

static int __init i2c_adap_imx_init(void)
{
	return platform_driver_register(&i2c_imx_driver);
}
subsys_initcall(i2c_adap_imx_init);
```

此时内存里已有一份「驱动说明书」；`platform_driver_register` 负责 **挂牌 + 找客户**。

### 6.2 总览

```text
platform_driver_register(&i2c_imx_driver)
        │
        ▼
┌───────────────────────────────────────────────────────────┐
│ A. 包装成通用 device_driver，挂到 platform 总线            │
│    __platform_driver_register                             │
│      · driver.bus   = &platform_bus_type                  │
│      · driver.probe = platform_drv_probe  ← 包装层        │
│      · 真正芯片 probe 仍是 i2c_imx_probe                  │
└────────────────────────────┬──────────────────────────────┘
                             │
                             ▼
┌───────────────────────────────────────────────────────────┐
│ B. 把驱动登记进驱动模型                                    │
│    driver_register → bus_add_driver                       │
│      · 进 platform 的 drivers 列表（sysfs 可见）          │
│      · drivers_autoprobe=1 → driver_attach(drv)           │
└────────────────────────────┬──────────────────────────────┘
                             │
                             ▼
┌───────────────────────────────────────────────────────────┐
│ C. 遍历 platform 总线上「已经存在」的每个 device          │
│    driver_attach → bus_for_each_dev → __driver_attach     │
│                                                           │
│    对每个 pdev：                                          │
│      driver_match_device → platform_match                 │
│           ├─ of_driver_match_device  ← 本板主路径         │
│           │    dts compatible 对 of_match_table           │
│           ├─ ACPI / id_table / 名字（兜底）               │
│           └─ 不匹配 → 下一个设备                          │
│      匹配成功 → driver_probe_device → really_probe        │
└────────────────────────────┬──────────────────────────────┘
                             │ 命中 i2c@021a0000 时
                             ▼
┌───────────────────────────────────────────────────────────┐
│ D. really_probe                                           │
│      1) pinctrl_bind_pins   ← 选 pinctrl_i2c1             │
│      2) drv->probe = platform_drv_probe                   │
│      3) platform_drv_probe → i2c_imx_probe(pdev)          │
│         （ioremap / clk / 注册 i2c-0 …）                  │
└───────────────────────────────────────────────────────────┘
```

前提：更早的 `of_platform_populate` 已根据 dtb 建好 `platform_device(i2c@021a0000)`。  
**设备先到、驱动后到**时，靠这次 `driver_attach` 绑定；反过来则是设备注册时 `device_attach` 找驱动——结果一样。

### 6.3 分步对照代码

#### A. 挂到 platform 总线

```c
/* drivers/base/platform.c：__platform_driver_register */
drv->driver.owner = owner;
drv->driver.bus = &platform_bus_type;
if (drv->probe)
	drv->driver.probe = platform_drv_probe;  /* 注意：不是直接挂 i2c_imx_probe */
return driver_register(&drv->driver);
```

```text
i2c_imx_driver                device_driver（通用）
┌─────────────────┐           ┌──────────────────────┐
│ .probe =        │           │ .bus = platform      │
│   i2c_imx_probe │──仍保留──▶│ .probe =             │
│ .driver.of_     │           │   platform_drv_probe │──稍后才调──▶ i2c_imx_probe
│   match_table   │──────────▶│ .of_match_table      │
└─────────────────┘           └──────────────────────┘
```

#### B. 进总线驱动列表并开始 attach

```text
driver_register                         drivers/base/driver.c
  └─ bus_add_driver                     drivers/base/bus.c
       ├─ klist_add_tail → 挂到 platform 的 drivers 链
       └─ driver_attach(drv)            drivers/base/dd.c
            └─ bus_for_each_dev(platform, __driver_attach)
                 对每个已有 platform_device 试一次
```

#### C. 匹配：`platform_match`

```c
/* drivers/base/platform.c：platform_match */
/* Attempt an OF style match first */
if (of_driver_match_device(dev, drv))
	return 1;
/* 然后 ACPI / id_table / 名字兜底 */
```

对本板：

```text
设备：i2c@021a0000
  compatible = "fsl,imx6ul-i2c", "fsl,imx21-i2c"

驱动：i2c_imx_dt_ids[]
  有 "fsl,imx21-i2c"（无单独 imx6ul 项）

of_match_device：按 compatible 列表逐项试
  "fsl,imx6ul-i2c" → 不在表里
  "fsl,imx21-i2c"  → 命中 ✓
```

其它 platform 设备（lcdif、fec…）对不上 `i2c_imx_dt_ids`，直接跳过。

#### D. 绑定：`really_probe` → 真正的 `i2c_imx_probe`

```text
__driver_attach（match 成功）
  → driver_probe_device
       → really_probe(dev, drv)                 drivers/base/dd.c
            ├─ pinctrl_bind_pins(dev)           drivers/base/pinctrl.c
            │    ← 消费 dts 里 pinctrl-0=&pinctrl_i2c1
            └─ drv->probe(dev)
                 = platform_drv_probe           drivers/base/platform.c
                      → drv->probe(pdev)        /* platform_driver* */
                           = i2c_imx_probe(pdev)
```

```c
/* drivers/base/platform.c：platform_drv_probe */
static int platform_drv_probe(struct device *_dev)
{
	struct platform_driver *drv = to_platform_driver(_dev->driver);
	struct platform_device *dev = to_platform_device(_dev);
	...
	ret = drv->probe(dev);   /* → i2c_imx_probe */
```

进 `i2c_imx_probe` 之后才是：ioremap `0x021a0000`、读 `clock-frequency`、`i2c_add_numbered_adapter` → 出现 `i2c-0`，并触发 `of_i2c_register_devices`（登记 `ap3216c@1e`）。详见 §五。

## 七、与屏 / 网匹配的对照

| 维度 | 屏 `09` | 网 `10` | **光感本文** |
|------|---------|---------|--------------|
| 总线类型 | platform（lcdif） | platform（fec）+ MDIO | **platform（i2c 控制器）+ I2C client** |
| 匹配键 | `compatible`（lcdif） | `compatible`（fec）+ phy | 控制器 `fsl,imx6ul-i2c`；从设备 **`LiteOn,ap3216c`** |
| 地址类属性 | MMIO `reg` | MMIO + PHY `reg` 站号 | 控制器 MMIO；从设备 **`reg=<0x1e>`** |
| pinctrl | lcdif dat/ctrl | enet + 复位 | **`pinctrl_i2c1`（SCL/SDA）** |
| 用户接口 | `/dev/fb0` | `eth0` | **`/dev/ap3216c` + sysfs** |

通用方法不变：**原理图 → dts 节点 → 驱动 of_match/id → probe → 用户态验证**。

## 八、失败时按层回查

| 现象 | 卡在哪一步 | 先查 |
|------|------------|------|
| 无 `/dev/i2c-0` | Step 1 | `I2C`/`I2C_IMX`、`&i2c1 status`、pinctrl |
| 有 i2c-0，`i2cdetect` 无 `1e` | 硬件/地址（匹配前） | 供电、脚、扫错总线号 |
| 有 `1e` 无 `UU`、无 `/dev/ap3216c` | Step 3～4 | 驱动未编进、`compatible`、只更了 dtb |
| `ap3216c init failed` | Step 4 写寄存器 | 地址/总线/器件未就绪 |
| `fxls8471 probe of 0-001e failed` | 旧冲突节点 | 仍加载含 `fxls8471@1e` 的 dtb |
| `dmesg` 无 ap3216 字样 | — | **成功时常如此**；看 `/dev/ap3216c` |

## 十、一句话

**`&i2c1` 打开控制器并配好 SCL/SDA → 子节点 `ap3216c@1e` 用 `reg`/`compatible` 建成 `0-001e` → `of_match` 命中 `LiteOn,ap3216c` 进入 `ap3216c_probe` → misc 出 `/dev/ap3216c`；`i2cdetect` 的 `UU` 表示该地址已被这条匹配链占用。**
