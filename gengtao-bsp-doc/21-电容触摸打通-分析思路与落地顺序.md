## 一、先定结论（避免走弯路）

1. **RGBLCD 电容触摸 ≠ SoC 内置电阻 TSC。**  
   你现在若只看到 `iMX6UL TouchScreen Controller`（`/dev/input/event1`），那是 **ADC 电阻屏控制器**，**不是** 原理图里 I2C2 上的电容触摸。
2. **正确路径：**

   ```text
   用户态（LVGL evdev / hexdump / 自写 app）
        ↑
   /dev/input/eventX（Goodix / FT5x06）
        ↑
   gt9xx 或 edt-ft5x06 驱动
        ↑
   I2C2 总线 + 设备树 goodix_ts@5d（或 edt-ft5x06@38）
        ↑
   硬件：屏 FPC ← I2C2_SCL/SDA + CT_INT + CT_RST
   ```

3. **进度（相对 `gengtao-bsp-0901`，2026-09-04）：**
   - **L0 已完成**：`i2cdetect -l` → I2C2=`i2c-1`（`21a4000.i2c`）；`i2cdetect -y 1` 见 **`5d`**；`i2cget`/`i2cdump` 可读 → **按 gt9xx @0x5d 继续**（未见 `38`）；
   - **L1 已完成（板上 + 宿主机 dtb 均已验收）**：`&tsc` disabled；hog 仅 12 cell（无 GPIO1_IO09）；板上仅剩电源键，无 `iMX6UL TouchScreen Controller`；
   - **L2 已完成（宿主机 dtb 已验收）**：`...-1024-600.dts` 已挂 `ts_int_pin` / `ts_reset_pin` + `goodix_ts@5d`；反编译见 `goodix,gt9xx` / `reg = <0x5d>`；`tsc` 仍 disabled；
   - **L3 已完成（板上已通过）**：`goodix-ts` → `/dev/input/event1`；曾修 lcdif pinctrl、`VSD_3V3` 抢 GPIO1_IO09、gt9xx 可选 regulator；
   - **L4 已完成（板上已通过）**：`hexdump -C /dev/input/event1` 摸屏有 EV_ABS 数据（见下）；
   - **L5 配置已落地（待板上点控确认）**：LVGL `EVDEV_NAME=/dev/input/event1`，`EVDEV_CALIBRATE=0`；`/root/demo` 已更新。
4. **推荐顺序：** L0 辨芯片地址 → L1 解除脚冲突 + 关 TSC → L2 加 dts 节点 → L3 引入 gt9xx 驱动 → L4 input 验收 → L5 改 LVGL `EVDEV_NAME`。
5. **显示已通即可开触摸；** 不要与电阻 TSC 校准（`EVDEV_CALIBRATE` 0～4095）混为一谈——电容屏坐标语义不同。

> **Goodix / FT5x06 名称从哪来？**  
> 原理图只标 I2C2 + CT_INT/CT_RST，**不写芯片型号**。名称来自 `origin/IMX6` 出厂 dts：`&i2c2` 下并列 `goodix_ts@5d`（`compatible = "goodix,gt9xx"`）与 `edt-ft5x06@38`，以及 `gt9xx.c` / 文档 **07**「后开 GT9xx」。**以板上 `i2cdetect` 为准**选路；本板已确认为 **`0x5d`**。

## 二、分析思路（为什么这样判断）

### 1. 从原理图抽出信号链

资料：

- `IMX6ULL_ALPHA_V2.4(底板原理图).pdf` → **RGBLCD** 40pin：`I2C2_SCL/SDA`、`CT_INT`、`CT_RST`
- `ATK-7RGBLCD(...).pdf` → 模组侧电容触摸 IC
- `IMX6ULL_CORE_V2.0(核心板原理图).pdf` → I2C2 / GPIO 经座子引出

```text
电容触摸 IC（屏上）
  VDD ── 模组供电（经 RGB 座）
  SCL ── RGBLCD.38 I2C2_SCL ← SoC UART5_TX → I2C2_SCL（板上 10K 上拉）
  SDA ── RGBLCD.36 I2C2_SDA ← SoC UART5_RX → I2C2_SDA（板上上拉）
  INT ── RGBLCD.39 CT_INT   ← SoC GPIO1_IO09
  RST ── RGBLCD.35 CT_RST   ← SoC GPIO5_IO09（SNVS_TAMPER9）
```

| 项 | 原理图事实 | 写进软件时 |
|----|------------|------------|
| 总线 | **I2C2**（SoC `i2c@021a4000`） | `&i2c2` 子节点 |
| 上拉 | SCL/SDA 底板有 10K→3V3 | 一般不必再配 open-drain 以外的事 |
| 中断 | **CT_INT → GPIO1_IO09** | `interrupts = <9 …>` + `irq-gpio` |
| 复位 | **CT_RST → GPIO5_IO09** | `rst-gpio` / `reset-gpios` |
| 同座显示 | LCDIF + BLT_PWM | 已在文档 **07** 打通；与触摸并行 |

对照表（写 pinctrl）：

| 板级信号 | SoC pad / GPIO | 宏 |
|----------|----------------|-----|
| I2C2_SCL | `UART5_TX_DATA` → I2C2_SCL | `MX6UL_PAD_UART5_TX_DATA__I2C2_SCL`（已有 `pinctrl_i2c2`） |
| I2C2_SDA | `UART5_RX_DATA` → I2C2_SDA | `MX6UL_PAD_UART5_RX_DATA__I2C2_SDA` |
| CT_INT | `GPIO1_IO09` | `MX6UL_PAD_GPIO1_IO09__GPIO1_IO09` → `ts_int_pin` |
| CT_RST | `SNVS_TAMPER9` → **GPIO5_IO09** | `MX6ULL_PAD_SNVS_TAMPER9__GPIO5_IO09` → `ts_reset_pin` |

说明：基线里已有 `pinctrl_lcdif_reset` 占用 **同一** `GPIO5_IO09`。出厂 `imx6ull-alientek-emmc.dts` 同样 **LCD 复位与 CT_RST 共脚**，另建 `ts_reset_pin` 指向该 pad 即可（与官方一致）。

### 2. 两条触摸通路对比（排错必看）

| | **电容（本文）** | **电阻 TSC（现状易混淆）** |
|--|------------------|---------------------------|
| 控制器 | 屏上 GT9xx / FT5x06 | SoC `tsc@02040000` |
| 总线 | I2C2 | ADC + `xnur-gpio` 等 |
| dmesg | `Goodix` / `gt9xx` / `edt_ft5x06` | `iMX6UL TouchScreen Controller` |
| 典型 event | 新 `eventX`（名称含 Goodix 等） | 现 `event1` |
| 坐标 | 接近屏分辨率 | ADC 约 0～0xFFF |
| LVGL | 直接跟手指；通常 **关** ADC 校准 | 需 `EVDEV_CALIBRATE` |
| 出厂 dts | `goodix_ts@5d` + 可选 `edt-ft5x06@38` | **`&tsc { status = "disabled"; }`** |

### 3. 从现有 dts 看出冲突点

当前 `imx6ull-14x14-evk-gengtao0901.dts`：

| 节点 / 组 | 问题 | 处理 |
|-----------|------|------|
| `pinctrl_hog_1` 含 `GPIO1_IO09` SD1 RESET | **占掉 CT_INT** | 从 hog **删掉**该行（NFS 启动一般不依赖 SD1 复位） |
| `&tsc` = okay | 噪声事件、误导 LVGL | **`status = "disabled"`** |
| `&i2c2` | 无触摸子节点 | 追加 `goodix_ts@5d`（和/或 ft5x06） |
| 无 `ts_int_pin` / `ts_reset_pin` | 中断/复位未复用到 GPIO | 按出厂片段补 |

出厂对照：

```bash
git -C ~/linux-imx6ull/linux-imx6ull-kernel-code \
  show origin/IMX6:arch/arm/boot/dts/imx6ull-alientek-emmc.dts | \
  sed -n '/edt-ft5x06@38/,/goodix_ts@5d/,+15p;/ts_int_pin/,+5p;/ts_reset_pin/,+5p;/\&tsc/,+8p'
```

### 4. 驱动选型（本树 4.1.15）

| 方案 | 说明 | 推荐 |
|------|------|------|
| **A. 正点原子 `gt9xx`（`compatible = "goodix,gt9xx"`）** | `origin/IMX6` + 本工程 `common/drivers/input/touchscreen/gt9xx.c`（L3 已引入） | **首选**（与出厂 dts 一致） |
| **B. `edt-ft5x06`** | 地址 **0x38**；出厂 dts 与 GT 并列 okay，probe 失败则跳过 | 模组确认为 FT 时用 |
| **C. 主线 `CONFIG_TOUCHSCREEN_GOODIX`** | compatible 多为 `goodix,gt911` 等，**与出厂 `goodix,gt9xx` 不同** | 除非改 dts compatible，否则不优先 |

defconfig / Kconfig：打开 **`CONFIG_TOUCHSCREEN_GT9XX=y`**（正点原子符号）；需要时可再开 `CONFIG_TOUCHSCREEN_EDT_FT5X06=y`。

### 5. I2C 总线号注意

SoC **硬件 I2C2**（`i2c@021a4000`）在本板 Linux 上对应 **`/dev/i2c-1`**；**I2C1**（`21a0000`，AP3216C）对应 **`i2c-0`**。扫电容触摸必须用 **`-y 1`**，不要扫到光感那条总线。

```bash

# 本板实测：
#   i2c-0    21a0000.i2c    ← 硬件 I2C1（AP3216C）
#   i2c-1    21a4000.i2c    ← 硬件 I2C2（电容触摸）
```

## 三、落地顺序（L0～L5）

### L0 — 辨芯片（可不改 dts）**【已通过 · 2026-09-04】**

**目的：**  
1. 锁定原理图上的 **I2C2** 对应哪个 `/dev/i2c-N`；  
2. 确认电容触摸从设备地址，从而在 **gt9xx（0x5d/0x14）** 与 **FT5x06（0x38）** 之间选型。

本步**不依赖**触摸驱动是否加载：`&i2c2` 已 okay、`pinctrl_i2c2` 已配、板上有上拉时，用内核 `i2c-dev` 即可探测。

#### L0.1 `i2cdetect -l` / `i2cdetect -y N` — 总线与地址

```bash
i2cdetect -l
i2cdetect -y 1          # I2C2 = i2c-1 时
```

**本板实测：**

```text
i2c-0   i2c        21a0000.i2c     I2C adapter
i2c-1   i2c        21a4000.i2c     I2C adapter

i2cdetect -y 1  →  地址 0x5d 有应答；无 0x38
```

| 命令结果 | 结论 | 为什么可以这样判 |
|----------|------|------------------|
| `i2c-1` → `21a4000.i2c` | 这就是 SoC **I2C2** | 与 `imx6ull.dtsi` 中 `i2c2: i2c@021a4000` 基址一致 |
| `0x5d` 有应答 | 屏上电容触摸在 I2C2 上；按 **Goodix / gt9xx** 继续 | 出厂 dts：`goodix_ts@5d`；原理图触摸走 I2C2 |
| **没有** `0x38` | 当前模组不是（或未接）FT5x06 主路径 | 出厂虽并列 `edt-ft5x06@38`，以实测为准 |
| （对比）若全 `--` | 线/电/复位/pinctrl 未通 | FPC、3V3、CT_RST、上拉、总线号是否搞错 |

**通过判据（地址层）：** 目标地址稳定出现在 `i2cdetect` → 本板为 **`5d`**。

> `i2cdetect` 只证明该 7-bit 地址 **ACK**，还不能代替驱动 probe；那是 L3。

#### L0.2 `i2cget` / `i2cdump` — 再确认「能读出数据」

比 `i2cdetect` 再强一步：不只 ACK，还从 `0x5d` **读回字节**。

```bash
i2cget -y 1 0x5d 0x00
i2cdump -y 1 0x5d
```

**本板实测摘要：**

```text
i2cget -y 1 0x5d 0x00  →  0x00

i2cdump -y 1 0x5d
  - 低地址区多为 00
  - 后半有非零（例如 0x42 处 0x59 显示为 'Y'；0x80 起有数据）
```

| 命令 | 工具在做什么 |
|------|----------------|
| `i2cget -y 1 0x5d 0x00` | 按 **SMBus 单字节**方式，读「寄存器地址 0x00」一个字节 |
| `i2cdump -y 1 0x5d` | 用同类方式，把从机 **0x00～0xFF** 扫一遍打印 |

| 能得出的结论 | 不能过度解读 |
|--------------|--------------|
| 从设备不只应答探测，**还能被读** → I2C2 上 `0x5d` **通信真实可用** | `i2cget ... 0x00`→`0x00` **≠**「芯片 ID = 0」 |
| 仍支持「按 gt9xx @0x5d 往下做」 | dump **不是** GT9xx 真实寄存器表的完整映像 |

**为何 dump 不能当手册对照：**  
GT9xx 内部是 **16 位寄存器地址**（产品 ID 等常在如 `0x8140` 一带）。`i2cget`/`i2cdump` 默认是 **8 位寄存器地址** 的简单读法，寻址方式与芯片不符时：

- 读「0x00」得到 `0x00` 很常见；  
- 前半大片 `00`、后半出现杂数据，只说明总线返回了字节，**不能**逐字节对照手册。

正确读产品 ID 需 16 位寻址的专用读法，或等 **gt9xx 驱动 probe** 打日志（L3）。

#### L0 合在一起（一句话）

```text
i2cdetect -l     → I2C2 = i2c-1（21a4000）
i2cdetect -y 1   → 0x5d 有从设备（ACK）
i2cget/i2cdump   → 还能读出数据（读写通）
```

→ **电容触摸在 I2C2 @0x5d，按 Goodix/gt9xx 打通；不是 FT(0x38)，也不是电阻 TSC。**

**L0 通过判据：** 上表三项均满足（本板已满足）。下一步 **L1**。

### L2 — 设备树挂电容触摸节点**【已完成 · 2026-09-04】**

**改动位置：** `imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dts`（overlay + 内核树已同步；已含 `#include <dt-bindings/gpio/gpio.h>`）。

在 `&iomuxc` / `&iomuxc_snvs` 增加（与出厂一致）：

```dts
ts_int_pin: ts_int_pin_mux {
	fsl,pins = <
		MX6UL_PAD_GPIO1_IO09__GPIO1_IO09	0x49
	>;
};

ts_reset_pin: ts_reset_pin_mux {
	fsl,pins = <
		MX6ULL_PAD_SNVS_TAMPER9__GPIO5_IO09	0x49
	>;
};
```

在 `&i2c2` 内追加（**本板只挂 GT**；L0 未见 `0x38`，不挂 FT，避免与 GT 抢同一 INT/RST）：

```dts
goodix_ts@5d {
	compatible = "goodix,gt9xx";
	reg = <0x5d>;
	status = "okay";
	pinctrl-names = "default";
	pinctrl-0 = <&ts_int_pin &ts_reset_pin>;
	interrupt-parent = <&gpio1>;
	interrupts = <9 0>;
	goodix,rst-gpio = <&gpio5 9 GPIO_ACTIVE_LOW>;
	goodix,irq-gpio = <&gpio1 9 GPIO_ACTIVE_LOW>;
};
```

> 注：`CT_RST`（GPIO5_IO09）与基线 `pinctrl_lcdif_reset` **同脚**，出厂 dts 亦如此。

00000000  97 69 01 00 d8 26 06 00  03 00 39 00 00 00 00 00  |....9.....|
00000010  97 69 01 00 d8 26 06 00  03 00 35 00 42 02 00 00  |....5.B...|
00000020  97 69 01 00 d8 26 06 00  03 00 36 00 32 01 00 00  |....6.2...|
00000030  97 69 01 00 d8 26 06 00  03 00 30 00 2f 00 00 00  |....0./...|
00000040  97 69 01 00 d8 26 06 00  03 00 32 00 2f 00 00 00  |....2./...|

**怎么读（本步你要盯的）：**

| hex 里常见 | 含义 |
|------------|------|

| `35 00` / `36 00` | `ABS_MT_POSITION_X` / `Y`（后面 4 字节为坐标小端） |
| `39 00` | `ABS_MT_TRACKING_ID`（`ff ff ff ff` = 抬起） |
| `00 00 00 00 …` | `EV_SYN` 同步一帧 |

## 五、排错速查

| 现象 | 先查 |
|------|------|
| `i2cdetect` 无 `5d`/`38` | FPC、3V3、I2C2 pinctrl、CT_RST 电平、总线号是否搞错（须 `i2c-1`/`21a4000`） |
| `i2cdetect` 有地址但 `i2cdump` 全失败 | 总线读异常、地址冲突、复位异常 |
| 把 `i2cdump` 当 GT 寄存器表 | GT 为 **16 位寄存器地址**；`i2cget`/`i2cdump` 默认 8 位寻址，仅作连通性参考 |
| dts 有节点但无驱动绑定 | `compatible` 是否为 **`goodix,gt9xx`**；是否编进 gt9xx；`dmesg` |
| `Error applying setting, reverse things back` | **pinctrl 抢脚**：常见 `&lcdif` 的 `pinctrl_lcdif_reset` 与 `ts_reset_pin` 同占 GPIO5_IO09；lcdif 只留 dat+ctrl（见 L3 修复） |
| `Failed to request GPIO… ERRNO:-16`（`-EBUSY`） | **GPIO 已被占用**：常见 `reg_sd1_vmmc` 的 `gpio=<&gpio1 9>` 占 CT_INT；按出厂注释掉 / `/delete-property/ gpio`（驱动报错 gpio 号可能印错） |
| probe 报 gpio / irq 失败 | GPIO1_IO09 是否仍被 hog/SD/`VSD_3V3` 占用；GPIO5_IO09 是否被其它驱动抢光 |
| `regulator get of vdd_ana failed` / `GTP power on failed` | dts 无触摸供电；本工程 gt9xx 已改为无 supply 则跳过 |
| `i2cdetect` 仍是 `5d` 不是 `UU` | probe 失败（见上）或驱动未绑到该 client |
| 仍只有 `iMX6UL TouchScreen` | dtb 未更新或 `&tsc` 未 disabled |
| LVGL 仍乱飘 | `EVDEV_NAME` 仍指向 TSC event；或未重新部署 demo |
| 能显示不能点 | event 号错；或仍用电阻校准把坐标映射坏 |

## 八、一句话

**RGBLCD 电容触摸 = I2C2（本板 `i2c-1`/`21a4000`）+ CT_INT(GPIO1_IO09) + CT_RST(GPIO5_IO09) + gt9xx@0x5d（本板 L0 已确认；未见 0x38）；关掉 `&tsc`，从 hog 释放 GPIO1_IO09，按 `origin/IMX6` 挂 `goodix_ts@5d` 并编进驱动；再用新 `event` 接 LVGL。不要把电阻 TSC 的 ADC 校准当成电容屏方案。**
