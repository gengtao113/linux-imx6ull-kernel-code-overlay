## 一、目标与触摸链

```text
用户态（hexdump / 将来 LVGL evdev）
      ↑
/dev/input/event1（Name=goodix-ts）
      ↑
gt9xx 驱动（compatible = "goodix,gt9xx"）
      ↑
I2C2（板上 i2c-1 / 21a4000）@ 0x5d
      ↑
CT_INT=GPIO1_IO09 + CT_RST=GPIO5_IO09 + I2C2_SCL/SDA
```

**易混点（开局就踩过）：** SoC 内置 **`iMX6UL TouchScreen Controller`** 是电阻 ADC TSC，**不是** RGBLCD 座上的电容触摸。电容路径必须走 I2C2 + gt9xx。

## 三、根因与修复（按踩坑顺序）

### 问题 1：把电阻 TSC 当成电容触摸

**现象：** `/proc/bus/input/devices` 只有（或曾有）`iMX6UL TouchScreen Controller`；LVGL 用 `event1` + ADC 校准 0～4095。

**根因：** 原理图 RGBLCD 电容触摸走 **I2C2 + CT_INT/CT_RST**；SoC TSC 是另一条硬件路径。

**修复：** L1 起 `&tsc { status = "disabled"; }`；后续只认 `goodix-ts`。

---

### 问题 2：`Error applying setting, reverse things back`

**现象（dmesg）：**

```text
goodix-ts 1-005d: Error applying setting, reverse things back
> GTP Driver Version: gt9xx driver Rleased <2021/11/27> Based V2.4
```

无 input 节点；`i2cdetect` 仍显示 `5d`（非 `UU`）。

**根因：** 基线 `&lcdif` 的 `pinctrl-0` 含 `&pinctrl_lcdif_reset`（**GPIO5_IO09**），与 goodix 的 `ts_reset_pin`（同脚 CT_RST）冲突。日志来自 `drivers/pinctrl/core.c`。

出厂 `alientek`：`&lcdif` **只挂** `dat` + `ctrl`，**不挂** `pinctrl_lcdif_reset`，复位脚留给触摸。

**修复（`…1024-600.dts`）：**

```dts
&lcdif {
	pinctrl-names = "default";
	pinctrl-0 = <&pinctrl_lcdif_dat
		     &pinctrl_lcdif_ctrl>;  /* 去掉 pinctrl_lcdif_reset */
	/* display + timings ... */
};
```

---

### 问题 3：`Failed to request GPIO:… ERRNO:-16`（`-EBUSY`）

**现象（完整启动日志关键段）：**

```text
<<-GTP-INFO->> GTP Driver Version: ...
<<-GTP-INFO->> GTP I2C Address: 0x5d
<<-GTP-ERROR->> Failed to request GPIO:137, ERRNO:-16
<<-GTP-ERROR->> GTP request IO port failed.
```

**根因：**

1. EVK 基线 `reg_sd1_vmmc`（`VSD_3V3`）有 `gpio = <&gpio1 9>`，占用 **CT_INT = GPIO1_IO09**。  
2. gt9xx 申请 INT gpio 时 `-EBUSY`。  
3. 厂商驱动报错时把 **rst/int 的 gpio 号印反了**：日志里的 `137`（= GPIO5_IO09）是 RST 编号，真正失败的是 INT。

出厂 `alientek` 已注释：

```dts
/* gpio = <&gpio1 9 GPIO_ACTIVE_HIGH>; */
```

**修复：**

```dts
&reg_sd1_vmmc {
	/delete-property/ gpio;
};
```

（NFS 启动不依赖该 SD 供电使能脚。）

### 问题 4：dts 无触摸 regulator，probe 可能在 `gtp_power_switch` 挂掉

> 说明：本板最终卡死在问题 2/3（pinctrl / GPIO EBUSY）。修好脚之后，读 `probe` 代码发现 **下一道闸** 就是供电；出厂驱动在无 `*-supply` 时会直接失败。因此在编进 zImage 前一并改掉，属于「读代码预判 + 防御性修复」，避免脚通了又在 power 上翻车。

#### 4.1 分析思路（怎么想到查供电）

`goodix_ts_probe()` 是一条**固定流水线**，前面任一步失败都不会注册 `input` 设备：

```text
probe 入口
  → 打 Version / I2C Address 日志
  → gtp_parse_dt()          （拿 irq/rst gpio 号）
  → gtp_request_io_port()   ← 问题 3 死在这里（-EBUSY）
  → i2c_check_functionality()
  → gtp_power_switch(on)    ← 问题 4 的位置（本条）
  → gtp_read_version / gtp_i2c_test / gtp_init_panel
  → gtp_request_input_dev() ← 成功才会出现 goodix-ts / eventN
  → gtp_request_irq()
```

思路：

1. **先看现象落在流水线哪一段**（有 Version 日志 = 已进 probe；无 `goodix-ts` = 中途 return）。  
2. **对照出厂 dts**：`goodix_ts@5d` 只有 `reg` / gpio / pinctrl，**没有** `vdd_ana-supply` / `vcc_i2c-supply`。  
3. **对照硬件**：ATK-7RGBLCD 触摸 IC 供电来自屏座/模组，一般不是 SoC 侧独立 regulator 节点。  
4. **再读 `gtp_power_switch`**：若 `regulator_get` 失败就 `return` 负值，而 probe 里 `if (ret) GTP power on failed; return -EINVAL` → **必然无 event**。

因此：即使当前日志还没打到这一行，修完 GPIO 后也很容易撞上；应把「无 supply 当可选」写进驱动。

#### 4.1.1 分析时对着看的日志（本板实测）

采集命令（建议固定用这一组，避免漏 GTP 前缀）：

```bash
dmesg | grep GTP
# 或更宽：
dmesg | grep -iE 'goodix|gt9|GTP|Error applying|Failed to request GPIO|regulator'
cat /proc/bus/input/devices
i2cdetect -y 1
```

**① 问题 2 阶段（pinctrl 抢脚，还没进到 power）——当时 grep 片段：**

```text
[root@gengtao ]# dmesg | grep -iE 'goodix|gt9|Error applying|pinctrl'
pinctrl core: initialized pinctrl subsystem
imx6ul-pinctrl 20e0000.iomuxc: initialized IMX pinctrl driver
imx6ul-pinctrl 2290000.iomuxc-snvs: initialized IMX pinctrl driver
goodix-ts 1-005d: Error applying setting, reverse things back
> GTP Driver Version: gt9xx driver Rleased <2021/11/27> Based V2.4
```

解读：已绑到 `1-005d`，但 pinctrl 失败；后面 Version 行来自 GTP 打印（grep 只因含 `gt9` 才扫到）。此时 **还轮不到** `gtp_power_switch`。

**② 问题 3 阶段（GPIO EBUSY）——完整启动里 GTP 关键段（分析流水线用）：**

```text
<<-GTP-INFO->> GTP driver installing...
<<-GTP-INFO->> GTP Driver Version: gt9xx driver Rleased <2021/11/27> Based V2.4
<<-GTP-INFO->> GTP I2C Address: 0x5d
<<-GTP-ERROR->> Failed to request GPIO:137, ERRNO:-16
<<-GTP-ERROR->> GTP request IO port failed.
```

对照流水线：

| 日志 | 含义 |
|------|------|
| `GTP driver installing...` | 模块/驱动注册 |
| `GTP Driver Version` / `I2C Address: 0x5d` | **已进入 `goodix_ts_probe()`** |
| `Failed to request GPIO… ERRNO:-16` | 死在 **`gtp_request_io_port()`**（问题 3） |
| （没有）`regulator get of vdd_ana failed` | **尚未执行到** `gtp_power_switch()` |
| （没有）`goodix-ts` 出现在 `/proc/bus/input/devices` | probe 已失败返回 |

同一时期旁证：

```text
[root@gengtao ]# cat /proc/bus/input/devices
# 仅有 snvs-powerkey / event0，无 goodix-ts

[root@gengtao ]# i2cdetect -y 1
# ... 5d ...   ← 仍是 5d，不是 UU（驱动未占用成功）
```

**③ 若 IO 已通、但未改 regulator 时，会接着打出（出厂驱动字符串，预判用）：**

```text
<<-GTP-INFO->> GTP Driver Version: ...
<<-GTP-INFO->> GTP I2C Address: 0x5d
<<-GTP-INFO->> Guitar reset          ← gtp_request_io_port 已成功才会有
<<-GTP-ERROR->> regulator get of vdd_ana failed
<<-GTP-ERROR->> GTP power on failed.
```

→ 据此锁定问题 4：死在 `gtp_power_switch()`，需改驱动或补 dts supply。

**④ 修改后期望（本工程 skip 路径）：**

```text
<<-GTP-INFO->> GTP Driver Version: ...
<<-GTP-INFO->> GTP I2C Address: 0x5d
<<-GTP-INFO->> Guitar reset
<<-GTP-INFO->> no vdd_ana/vcc_i2c supply in DT, skip regulator control
<<-GTP-INFO->> X_MAX: ..., Y_MAX: ..., TRIGGER: ...
<<-GTP-INFO->> GTP works in interrupt mode.   # 或 polling mode
# /proc/bus/input/devices 出现 Name="goodix-ts" Handlers=event1
```

> 若内核给无 supply 的 `regulator_get` 返回 dummy 而非 ERR，也可能**看不到** skip 那行 INFO，但 probe 仍能过；本改动保证「ERR 路径也不杀 probe」。

#### 4.2 问题定位（代码与机制）

**调用点**（`goodix_ts_probe` 内，IO 口申请成功之后）：

```c
ret = gtp_power_switch(client, 1);
if (ret) {
    GTP_ERROR("GTP power on failed.");
    return -EINVAL;   /* probe 失败，不会注册 input */
}
```

**出厂实现（`origin/IMX6` 原版，失败即返回错误）：**

```c
vdd_ana = regulator_get(&client->dev, "vdd_ana");
if (IS_ERR(vdd_ana)) {
    GTP_ERROR("regulator get of vdd_ana failed");
    return PTR_ERR(vdd_ana);   /* 常见 -ENODEV / -EPROBE_DEFER */
}
/* vcc_i2c 同理，失败也 return */
```

`regulator_get(dev, "vdd_ana")` 会在设备节点上找属性 **`vdd_ana-supply`**。我们的 `goodix_ts@5d` **没有写**，内核 regulator 框架拿不到有效 consumer 映射 → `IS_ERR(...)` 为真。

失败时的 GTP 打印见上文 **§4.1.1 ③**；成功 skip 见 **§4.1.1 ④**。

#### 4.3 如何修改、改了哪里

| 项 | 内容 |
|----|------|
| **文件** | `linux-kernel-overlay/common/drivers/input/touchscreen/gt9xx.c` |
| **函数** | `gtp_power_switch()`（约 632 行起） |
| **策略** | 有 supply → 照旧 enable/disable；**没有** → INFO 提示后 `return 0`，当作「常供电、无需内核管电」 |
| **同步** | apply_overlay / 拷到内核树同路径 → 重编 `zImage` → 更新 `tftpboot/zImage` |

**修改要点（相对出厂）：**

1. 增加静态标志 `skip_regulator`：一旦判定无 supply，后续 suspend/resume 再调 power 也直接成功返回。  
2. `regulator_get("vdd_ana")` 失败时：**不再** `GTP_ERROR` + `return PTR_ERR`，改为 `GTP_INFO` + `skip_regulator=true` + `return 0`。  
3. `vcc_i2c` 同理；若已拿到 `vdd_ana` 再发现无 `vcc_i2c`，`regulator_put(vdd_ana)` 后同样跳过。  
4. **probe() 里调用关系未改**——仍调用 `gtp_power_switch(client, 1)`；只是函数语义从「必须有电轨」变为「有则控、无则跳过」。

**现行代码骨架：**

```c
static int gtp_power_switch(struct i2c_client *client, int on)
{
    static struct regulator *vdd_ana;
    static struct regulator *vcc_i2c;
    static bool skip_regulator;
    int ret;

    if (skip_regulator)
        return 0;

    if (!vdd_ana) {
        vdd_ana = regulator_get(&client->dev, "vdd_ana");
        if (IS_ERR(vdd_ana)) {
            GTP_INFO("no vdd_ana/vcc_i2c supply in DT, skip regulator control");
            skip_regulator = true;
            return 0;   /* ★ 关键：失败当「可选」，不拖垮 probe */
        }
    }
    /* vcc_i2c 获取失败时同样 skip_regulator + return 0 */

    if (on) {
        regulator_enable(vdd_ana);
        udelay(2);
        regulator_enable(vcc_i2c);
    } else {
        regulator_disable(vcc_i2c);
        udelay(2);
        regulator_disable(vdd_ana);
    }
    return ret;
}
```

**若将来 dts 真要内核管电**，在 `goodix_ts@5d` 补上即可，例如：

```dts
vdd_ana-supply = <&reg_xxx>;
vcc_i2c-supply = <&reg_yyy>;
```

有 supply 时走原 enable/disable 路径，与本次修改兼容。

## 七、经验沉淀

1. **先辨硬件路径**：电容 = I2C2；电阻 TSC = SoC ADC——名字里有 TouchScreen 不等于电容屏。  
2. **出厂 dts 是抢脚说明书**：`alientek` 里 lcdif 不挂 reset、`VSD_3V3` 注释掉 `gpio1 9`，都是为触摸让路；EVK 基线默认会冲突。  
3. **两层资源冲突要分开查**：  
   - pinctrl 冲突 → `Error applying setting`  
   - gpio_request 冲突 → `-EBUSY`  
4. **厂商驱动日志不可全信**：gpio 号可能印错；以 `of_get_named_gpio` 语义 + `/sys/kernel/debug/gpio`（若有）交叉验证。  
5. **event 号看 devices，不猜**：本板 `event0`=电源键，`event1`=goodix。  
6. **验收分层**：dtb 反编译（L2）≠ probe 成功（L3）≠ 摸屏有事件（L4）≠ 应用可点（L5）。  
7. **与显示复盘同一纪律**：只改 overlay；改完同步内核树；TFTP 确认 Loading done；`dtc`/`dmesg`/`devices` 三件套。

## 八、一句话

**电容触摸打通的主线是「辨 I2C2@0x5d → 关 TSC → 挂 goodix 节点 → 编进 gt9xx → 把 EVK 占脚的 lcdif-reset / VSD_3V3 让出来」；板上最终以 `goodix-ts` + `/dev/input/event1` + hexdump 摸屏为准。下一步把 LVGL `EVDEV_NAME` 指到 event1。**
