## 一、先定结论（避免走弯路）

1. **LED0 走内核 LED 子系统，不自己写驱动。** 内核已带 `drivers/leds/leds-gpio.c`，且 defconfig 已开 `CONFIG_LEDS_GPIO=y` 等；LED 就是「GPIO 拉高/拉低」，没有寄存器时序，不值得自写 misc 驱动（对比 AP3216C/ICM20608 那类才需要自写）。
2. **正确路径：**

   ```text
   应用（echo > brightness / 切 trigger）
        ↑
   /sys/class/leds/sys-led/brightness
        ↑
   leds-gpio 驱动（compatible = "gpio-leds"）
        ↑
   设备树 leds 节点 + gpios = <&gpio1 3 GPIO_ACTIVE_LOW>
        ↑
   硬件：VCC_3V3 → 510Ω(R9) → LED0 阳极，阴极 → GPIO1_IO03（共阳，低电平亮）
   ```

3. **进度（相对 `gengtao-bsp-0901`，2026-09-05）：** L0～L5 均未开始，本文为首次落地。
4. **推荐顺序：** L0 辨脚 → L1 加 dts 节点 → L2 核对内核配置 → L3 编译 + 反编译核对 → L4 sysfs 验收 → L5 应用层点灯 / trigger。

> **为什么是「低电平亮」？** 底板 LED 是**共阳**接法：`VCC_3V3 → 510Ω → LED 阳极`，`LED 阴极 → GPIO1_IO03`。GPIO 拉低（=0）时电流才导通 → LED 亮；拉高（=1）时截止 → 灭。内核 LED 框架用 `GPIO_ACTIVE_LOW` 帮你把「亮度 1=亮」自动反相到「GPIO 输出 0」，应用层别再自己取反。

## 二、分析思路（为什么这样判断）

### 1. 从原理图抽出信号链

资料（`gengtao-bsp-doc/` 下两份 PDF）：

- `IMX6ULL_ALPHA_V2.4(底板原理图).pdf` → LED0（DS0）、`R9 510Ω`、底板网 **`GPIO_3`**
- `IMX6ULL_CORE_V2.0(核心板原理图).pdf` → `GPIO_3` 经核心板座引出，对应 SoC 脚 **GPIO1_IO03**

```text
LED0(DS0) 阴极 ── 底板网 "GPIO_3" ── 核心板座(L17/J2_47) ── SoC GPIO1_IO03
LED0(DS0) 阳极 ── R9 510Ω ── VCC_3V3
```

### 2. 底板网名 `GPIO_3` ≠ SoC 脚号，别搞混

- 底板上那批座子网名是 **`GPIO_1`、`GPIO_2`、`GPIO_3`…`GPIO_9`**，是**底板自己起的排针名**，不是 SoC 的 `GPIO1_IOxx` 编号。
- 映射关系（本板常用，`04` 文档第四节也有）：
  - `GPIO_1` → GPIO1_IO01（AP3216C 中断 / KEY0 跳线共用）
  - `GPIO_3` → **GPIO1_IO03**（LED0）
  - `GPIO_8` → GPIO1_IO08（BLT_PWM 背光）
  - `GPIO_9` → GPIO1_IO09（电容触摸 CT_INT）
- 所以 **LED0 = GPIO1_IO03**，在 dts 里写 `gpios = <&gpio1 3 ...>`（第 1 组 GPIO、脚 3），**不是** `&gpio3`。

### 3. GPIO1_IO03 标号含义（命名规则）

`GPIO1_IO03` 是 i.MX6ULL 的引脚命名，拆成两段：

```text
GPIO1   +   IO03
  │          │
  │          └── 组内第 3 号脚（0～31）
  └── 第 1 组 GPIO 控制器（bank）
```

| 部分 | 含义 |
|------|------|
| `GPIO1` | 第 1 组 GPIO（i.MX6ULL 共 5 组：GPIO1～GPIO5） |
| `IO03` | 组内第 3 个脚（每组 32 个：IO00～IO31） |

**与 dts 写法对应：** 设备树不写 `GPIO1_IO03`，写成「控制器 + 组内偏移」：

```dts
gpios = <&gpio1 3 GPIO_ACTIVE_LOW>;
           │    └── 组内偏移 3（= IO03）
           └── 引用 GPIO1 控制器节点
```

即 `&gpio1 3` = `GPIO1_IO03`（附录 B「别写成 `&gpio3 3`」就是这个意思）。

**与 Linux 全局号对应：** 内核内部还有一个全局连续号（旧 `/sys/class/gpio` 用）：

```text
全局号 = (组号 - 1) × 32 + 组内偏移 = (1 - 1) × 32 + 3 = 3
```

所以 `GPIO1_IO03` 的全局号是 **gpio3**（`GPIO5_IO01` 则是 `4×32+1=129`）。用 leds-gpio 时**不必碰全局号**，dts 里 `&gpio1 3` 即可。

**原理图里 `GPIO1_IO03/I2C1_SDA/GPT1_COMPARE3/...` 的 `/` 是什么意思：** 一个物理焊盘（pad）有多个复用功能，靠 IOMUX 切换：

- 复用成 GPIO → `GPIO1_IO03`
- 复用成 I2C1 数据线 → `I2C1_SDA`
- 复用成定时器比较输出 → `GPT1_COMPARE3`

同一时刻只能选一个。LED0 要用它，就把它 mux 成 GPIO（L1 里 `MX6UL_PAD_GPIO1_IO03__GPIO1_IO03`），前提是别的复用（尤其 `I2C1_SDA`）没被占用——L0 已确认本板不冲突。

### 4. 共阳电路 → 低电平点亮（active-low）

- 原理图：LED 阳极经 `R9 510Ω` 接 `VCC_3V3`，阴极接 GPIO → **共阳**。
- 结论：`GPIO1_IO03 = 0` → LED 亮；`= 1` → 灭。dts 里用 **`GPIO_ACTIVE_LOW`** 表达。
- 好处：内核 LED 框架据此自动反相，你写 `brightness=1` 就是「亮」，写 `0` 就是「灭」，不用记低电平。

### 5. 驱动选型对比

| 方案 | 是否推荐 | 理由 |
|------|---------|------|
| **A. `leds-gpio`（`compatible="gpio-leds"`）** | **首选** | 内核自带、defconfig 已开、出厂 dts 同款，标准做法 |
| B. 老 sysfs GPIO（`/sys/class/gpio`） | 不推荐 | 内核 4.x 后已废弃，仅临时调试 |
| C. 自写 misc/字符驱动 | 不必要 | LED 无协议时序，学习性 > 必要性 |

### 6. 出厂 dts 就是现成答案

`origin/IMX6` 分支 `imx6ull-alientek-emmc.dts` 里已有完整节点（本次基本照搬）：

```dts
leds {
    compatible = "gpio-leds";
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_gpio_leds
             &pinctrl_beep>;

    led1 {
        label = "sys-led";
        gpios = <&gpio1 3 GPIO_ACTIVE_LOW>;
        linux,default-trigger = "heartbeat";
        default-state = "on";
    };

    beep {
        label = "beep";
        gpios = <&gpio5 1 GPIO_ACTIVE_LOW>;
        default-state = "off";
    };
};
```

> 出厂节点同时挂了 `beep`（GPIO5_IO01）。本文只做 **LED0**；beep 留到后续（原理图 `04` 里 LED/KEY/BEEP 归为一组）。

### L0 — 辨硬件连接**【已完成 2026-09-05】**

不改代码，先确认脚对不对、会不会冲突。逐条核对了当前 dts，结果如下。

1. **看原理图**：LED0 = `GPIO_3` → GPIO1_IO03，共阳、低电平亮。✅（与 origin/IMX6 出厂 `leds` 节点一致）

2. **确认 GPIO1_IO03 复用脚不被占** —— 实测发现真正占用方是 **TSC（电阻触摸）**，不是 I2C1：
   - **I2C1_SDA 复用：无冲突。** I2C1 走 UART4 复用（基板 dts `pinctrl_i2c1`：`UART4_TX_DATA__I2C1_SCL` / `UART4_RX_DATA__I2C1_SDA`，基板 dts 411–412 行），没占 GPIO1_IO03 的 I2C1_SDA 复用。✅
   - **TSC 复用：基板 dts 里 `&tsc` 仍 `status="okay"`**，且 `pinctrl_tsc` 占用 `MX6UL_PAD_GPIO1_IO03__GPIO1_IO03`（基板 dts 492 行）、`xnur-gpio = <&gpio1 3 GPIO_ACTIVE_LOW>`（基板 dts 724 行）—— 电阻触摸的 Xn/Ur 线就是 GPIO1_IO03。⚠️
   - **但实际启动的 1024-600 dts 里 `&tsc` 已 `status="disabled"`**（触摸打通时关的，1024-600 dts 91 行），运行时 tsc 不 probe、不申请该 GPIO、不 apply `pinctrl_tsc` → **GPIO1_IO03 实际空闲**。✅

3. **记下 dts 写法**：`gpios = <&gpio1 3 GPIO_ACTIVE_LOW>`（**gpio1 + 脚号 3**，不是 gpio3）。✅

4. **编译目标确认**：Makefile 只编 `imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dtb`（include 基板 dts + override `&tsc=disabled`），故上板最终配置里 tsc 已关，LED0 无冲突。

**结论 / 通过判据：** LED0 在 GPIO1_IO03、低电平亮；唯一占用方是 `&tsc`（电阻触摸），已被 1024-600 dts 关掉 → **无运行时冲突，L0 通过**。

> **约束：`&tsc` 必须保持 disabled，不能开回来。** 对 L1 的影响：leds 节点放基板 dts 可行（最终 dtb 里 tsc 已关）；但若哪天要开回电阻触摸，需先让出 GPIO1_IO03。

```dts
/* iomuxc */
pinctrl_gpio_leds: gpio-leds {
    fsl,pins = <
        MX6UL_PAD_GPIO1_IO03__GPIO1_IO03  0x17059
    >;
};
```

## 附录 B：易踩的坑

| 坑 | 正确做法 |
|----|---------|
| 把底板网名 `GPIO_3` 当 SoC 脚号，写成 `&gpio3 3` | LED0 是 **GPIO1_IO03** → `&gpio1 3` |
| 忘记 active-low，写 `GPIO_ACTIVE_HIGH` | 共阳电路，必须 `GPIO_ACTIVE_LOW`，否则亮度方向反 |
| 应用层又自己取反（以为要写 0 才亮） | 框架已反相，**`brightness=1` 就是亮**，别二次取反 |

| 复用冲突：GPIO1_IO03 被 I2C1_SDA 占用 | 本板 I2C1 走 UART4 复用，不冲突；其它板要查 |
| 改完 dts 没同步/没编对 dtb | 走 overlay 同步流程 + 反编译核对（L3） |

## 附录 D：pinctrl 单行拆解（`MX6UL_PAD_...__...  0x17059`）

L1 里那行：

```dts
MX6UL_PAD_GPIO1_IO03__GPIO1_IO03  0x17059
```

由「宏 + 配置值」两部分组成，整体含义：**把 GPIO1_IO03 这颗 pad 复用成 GPIO（ALT5），并配成 100MHz / R0/3 驱动 / 快斜率 / 推挽输出**。

### 宏 `MX6UL_PAD_<焊盘>__<功能>`

命名格式是 `MX6UL_PAD_<焊盘>__<功能>`：

| 部分 | 含义 |
|------|------|
| `GPIO1_IO03`（`__` 左边） | 要配置的**物理引脚**（pad） |
| `GPIO1_IO03`（`__` 右边） | 复用成的**功能** = GPIO1 组第 3 号 GPIO |

定义在 `imx6ul-pinfunc.h`，展开成 5 个数字：

```c
#define MX6UL_PAD_GPIO1_IO03__GPIO1_IO03  0x0068 0x02F4 0x0000 0x5 0x0
```

| 字段 | 值 | 含义 |
|------|-----|------|
| `0x0068` | mux 寄存器偏移 | `SW_MUX_CTL_PAD_GPIO1_IO03`，决定复用成哪个功能 |
| `0x02F4` | conf 寄存器偏移 | `SW_PAD_CTL_PAD_GPIO1_IO03`，决定电气属性（`0x17059` 写进这里） |
| `0x0000` | input 寄存器偏移 | 输入复用（daisy）选择，0 = 本脚不需要 |
| `0x5` | **mux 模式** | **ALT5 = GPIO**（把 pad 复用成 GPIO1_IO03） |
| `0x0` | input 选择值 | 配 input 寄存器用，这里为 0 |

同一焊盘换复用（`__` 右边换名，第 4 字段跟着变）：

```c
MX6UL_PAD_GPIO1_IO03__I2C1_SDA        ... 0x0 0x1   /* ALT0 = I2C1_SDA */
MX6UL_PAD_GPIO1_IO03__GPT1_COMPARE3   ... 0x1 0x0   /* ALT1 */
MX6UL_PAD_GPIO1_IO03__GPIO1_IO03      ... 0x5 0x0   /* ALT5 = GPIO ← 我们用 */
MX6UL_PAD_GPIO1_IO03__UART1_DCE_RX    ... 0x8 0x1   /* ALT8 */
```

### 配置值 `0x17059`

写进 `SW_PAD_CTL` 寄存器的配置字，每个 bit 一种电气属性：

```text
0x17059 = 0b 1 0111 0000 0101 1001
```

| Bit | 字段 | 值 | 含义 |
|-----|------|-----|------|
| 16 | HYS | 1 | 迟滞使能（输入波形整形） |
| 15–14 | PUS | 01 | 47kΩ 上拉 |
| 13 | PUE | 1 | 选 pull 而非 keeper |
| 12 | PKE | 1 | 上拉/keeper 使能 |
| 11 | ODE | 0 | 非开漏，推挽输出 |
| 10–8 | — | 000 | 保留 |
| 7–6 | SPEED | 01 | 100 MHz 速度档 |
| 5–3 | DSE | 011 | 驱动强度 R0/3 |
| 2–1 | — | 00 | 保留 |
| 0 | SRE | 1 | 快斜率（fast slew） |

对 LED0 最关键的是 `ODE=0`（推挽，能正常灌电流点亮 LED）。注意 **`SION` 不在这里**：`SION` 是 MUX 寄存器 `SW_MUX_CTL` 的 bit4（软件输入常开），不在 `SW_PAD_CTL` 里；`0x17059` 只配电气，不含 SION。

## 附录 E：内核配置逆向确定方法（从 compatible 追到要开哪些 CONFIG）

L2 里「怎么知道要开这几个宏」的完整套路，一句话：**从 dts 的 `compatible` 出发，逆向追到 `Makefile` 的 `obj-$(CONFIG_X)`，再到 `Kconfig` 的 `depends on`**。以后任何外设都能照此办。以 LED0 为例走一遍：

### 第 1 步：`compatible` → 驱动源文件

dts 里 `compatible = "gpio-leds"`，内核据此匹配驱动。查 `drivers/leds/leds-gpio.c`：

```c
static const struct of_device_id of_gpio_leds_match[] = {
    { .compatible = "gpio-leds", },
};
```

→ 命中 `leds-gpio.c`，这就是要编进内核的驱动。

### 第 2 步：驱动源文件 → CONFIG 宏

该源文件是否编译，由所在目录的 `Makefile` 决定。`drivers/leds/Makefile`：

```make
obj-$(CONFIG_LEDS_GPIO) += leds-gpio.o
```

→ 要编 `leds-gpio.c` 就得开 `CONFIG_LEDS_GPIO`。

### 第 3 步：CONFIG 宏 → 依赖（depends on）

光开 `LEDS_GPIO` 不够，它还有前置依赖。`drivers/leds/Kconfig`：

```kconfig
config LEDS_GPIO
    tristate "LED Support for GPIO connected LEDs"
    depends on LEDS_CLASS
    depends on GPIOLIB
```

→ 还要 `CONFIG_LEDS_CLASS`（`GPIOLIB` 是 GPIO 子系统，ARM 平台必开）。

### 第 4 步：`LEDS_CLASS` 的作用 = sysfs

`LEDS_CLASS` 的 Kconfig help 原文：

> This option enables the led sysfs class in `/sys/class/leds`.

对应 `drivers/leds/Makefile` 的 `obj-$(CONFIG_LEDS_CLASS) += led-class.o`。

### 第 5 步：`NEW_LEDS` 是总开关

Kconfig 里 `menuconfig NEW_LEDS … if NEW_LEDS` 把上面所有 `LEDS_*` 都包起来，不开 `NEW_LEDS` 下面不出现。

### 第 6 步（可选）：trigger

L5 心跳/定时闪烁要 trigger：框架 `CONFIG_LEDS_TRIGGERS` + 具体触发器。`drivers/leds/trigger/Makefile`：

```make
obj-$(CONFIG_LEDS_TRIGGER_TIMER)      += ledtrig-timer.o
obj-$(CONFIG_LEDS_TRIGGER_HEARTBEAT)  += ledtrig-heartbeat.o
```

### 汇总（本 LED0 最小集合）

| 需求 | 对应 CONFIG | 本板状态 |
|------|-------------|---------|
| LED 子系统总开关 | `CONFIG_NEW_LEDS` | =y |
| `/sys/class/leds` 接口 | `CONFIG_LEDS_CLASS` | =y |
| `gpio-leds` 驱动 | `CONFIG_LEDS_GPIO` | =y |
| trigger 框架 | `CONFIG_LEDS_TRIGGERS` | =y |
| 心跳 / 定时触发器 | `CONFIG_LEDS_TRIGGER_HEARTBEAT` / `..._TIMER` | =y |

> **通用口诀：** `compatible`（dts）→ `of_match`（.c）→ `obj-$(CONFIG_X)`（Makefile）→ `depends on`（Kconfig）→ `menuconfig` 总开关。拿到任何一个外设，先找它的 `compatible` 字符串，剩下顺着这条链走就全知道了。
