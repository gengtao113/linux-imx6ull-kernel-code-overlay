## 一、先定结论（避免走弯路）

1. **不要从 MCU/裸机示例重写一套 Linux 驱动。**  
   `100ask` 裸机 `ap3216c.c` 只证明寄存器语义；Linux 上正点原子出厂已有字符设备驱动。
2. **正确路径：**

   ```text
   用户态 ioctl / sysfs（ir、als、ps）
        ↑
   /dev/ap3216c（misc + I2C client）
        ↑
   drivers/char/ap3216c.c（origin/IMX6 已有）
        ↑
   I2C1 总线 + 设备树节点 ap3216c@1e
        ↑
   硬件：U9 AP3216C ← I2C1_SCL/SDA；INT→AP_INT→GPIO1_IO01
   ```

3. **进度（相对 `gengtao-bsp-0901`，2026-09-03）：**
   - **L1** 已去掉 `fxls8471@1e`，挂上 `ap3216c@1e`；
   - **L2** `i2cdetect`/`i2cget` 已通；
   - **L3** 已引入驱动，板上 `/dev/ap3216c` 存在；**L4** `i2cdetect` 见 `UU`，sysfs 可读 `als`（待遮光/靠近对照后结案）。
4. **中断脚可第二阶段再接。** 出厂驱动用轮询读寄存器，不依赖 `AP_INT`；先通 I2C + 读数即可。

## 二、分析思路（为什么这样判断）

### 1. 从原理图抽出信号链

资料：

- `IMX6ULL_ALPHA_V2.4(底板原理图).pdf` → DEVICE1：**ALS&PS SENSOR（U9 AP3216C）**
- `IMX6ULL_CORE_V2.0(核心板原理图).pdf` → I2C1 / GPIO_1 座子引出

```text
AP3216C (U9)
  VDD / LEDA ── VCC_3V3（C19 1uF、C20/C88 100nF）
  SCL ──────── I2C1_SCL
  SDA ──────── I2C1_SDA
  INT ──────── AP_INT ── 核心板座 J2_49「GPIO_1」── SoC GPIO1_IO01
  GND ──────── GND
```

| 项 | 原理图事实 | 写进软件时 |
|----|------------|------------|
| 总线 | **I2C1** | `&i2c1` 子节点 |
| 7bit 地址 | 固定 **0x1E** | `reg = <0x1e>` |
| 供电 | `VCC_3V3`，无独立使能脚 | 一般不写 regulator |
| 中断 | `AP_INT` → **GPIO1_IO01** | 可选；首轮可省略 |
| I2C1 pad | 核心板 `UART4_TXD/RXD` 复用 I2C1 | 已有 `pinctrl_i2c1` |

核心板脚位（写 pinctrl / 中断时用）：

| 板级名 | SoC pad / GPIO | 说明 |
|--------|----------------|------|
| I2C1_SCL | `UART4_TX_DATA` → I2C1_SCL | `MX6UL_PAD_UART4_TX_DATA__I2C1_SCL` |
| I2C1_SDA | `UART4_RX_DATA` → I2C1_SDA | `MX6UL_PAD_UART4_RX_DATA__I2C1_SDA` |
| GPIO_1 / AP_INT | **GPIO1_IO01** | 与 KEY0 可能经跳线共用，配中断前核对拨码 |

### 2. 从现有 dts 看出冲突点

当前 `imx6ull-14x14-evk-gengtao0901.dts`（EVK 遗留）：

```dts
&i2c1 {
    mag3110@0e { ... };      /* EVK 磁力计，ALPHA 可无 */
    fxls8471@1e { ... };     /* EVK 加速度计 @0x1E —— 与 AP3216C 冲突 */
};
```

ALPHA 板上 **0x1E 是 AP3216C**，不是 fxls8471。  
不删/不禁 `fxls8471@1e`，即使加了 `ap3216c@1e` 也会地址冲突或错误驱动绑死。

### 3. 从出厂实现验证路径（`origin/IMX6`）

```bash
# 设备树节点
git -C ~/linux-imx6ull/linux-imx6ull-kernel-code \
  show origin/IMX6:arch/arm/boot/dts/imx6ull-14x14-evk.dts | sed -n '/&i2c1/,/^};/p'

# 驱动与配置
git -C ~/linux-imx6ull/linux-imx6ull-kernel-code \
  show origin/IMX6:drivers/char/ap3216c.c | head
git -C ~/linux-imx6ull/linux-imx6ull-kernel-code \
  show origin/IMX6:include/linux/ap3216c.h
# Kconfig: CONFIG_LITEON_AP3216C
# Makefile: obj-$(CONFIG_LITEON_AP3216C) += ap3216c.o
# defconfig: CONFIG_LITEON_AP3216C=y
```

出厂 dts 要点：

```dts
&i2c1 {
    mag3110@0e { status = "disabled"; };
    ap3216c@1e {
        compatible = "ap3216c";
        reg = <0x1e>;
    };
};
```

出厂驱动要点：

| 项 | 内容 |
|----|------|
| 匹配 | `of_match`：`LiteOn,ap3216c`；`i2c_device_id`：`ap3216c` |
| probe | 写 `0x00=0x04` 软复位 → `mdelay(50)` → 写 `0x00=0x03` 开 IR/ALS/PS |
| 用户接口 | misc **`/dev/ap3216c`** + ioctl；另有 sysfs `ir` / `als` / `ps` |
| 中断 | **未使用** GPIO / `AP_INT` |

**compatible 建议：** dts 同时写 `"LiteOn,ap3216c", "ap3216c"`，避免 of_match 与 id_table 路径不一致。

### 4. 寄存器语义（对照裸机/手册，便于调不通时查）

| 寄存器 | 偏移 | 用途 |
|--------|------|------|
| SYSTEMCONFIG | `0x00` | `0x04` 软复位；`0x03` 使能 ALS+PS+IR |
| INTSTATUS / INTCLEAR | `0x01` / `0x02` | 中断（本驱动首轮不用） |
| IR DATA | `0x0A` / `0x0B` | IR 低/高 |
| ALS DATA | `0x0C` / `0x0D` | ALS 低/高 |
| PS DATA | `0x0E` / `0x0F` | PS 低/高 |

## 三、落地顺序（建议严格按层做）

> 原则与网口/屏相同：**先总线探测 → 再绑驱动 → 再用户态读数**；中断最后加。  
> **每层做完必须过本层「完成后验证」再进入下一层**，避免问题堆到最后难拆。

### 分层验证总览（速查）

| 层 | 做完后至少确认 | 不通过时先查 |
|----|----------------|--------------|
| **L0** | 有 `/dev/i2c-*`；适配器已注册 | I2C 三项 config、`&i2c1 status`、pinctrl |
| **L1** | dtb 反编译可见 `ap3216c@1e`，**无** `fxls8471@1e` | 是否改错文件 / 未重编 dtb / U-Boot 仍加载旧 dtb |
| **L2** | `i2cdetect` 见 **`1e` 或 `UU`** | 供电、脚、冲突器件、总线号 |
| **L3** | `.config` 有 `CONFIG_LITEON_AP3216C=y`；zImage 已更新 | overlay 未 apply、只更了 dtb |
| **L4** | `/dev/ap3216c` + ALS/PS 随环境变化 | probe/init failed、compatible、地址 |
| **L5** | （可选）INT 脚为 GPIO；驱动侧确已 `request_irq` | KEY0 跳线、驱动未改却期望中断 |

### L0 — 确认 I2C1 已启用（多数板已 okay）

> **本工程现状（`gengtao-bsp-0901`）**：板级 dts 里 `&i2c1 { status = "okay"; pinctrl-0 = <&pinctrl_i2c1>; }` 已写好；内核 `.config` 中下列三项亦已 `=y`。L0 **无需再为「打开 I2C1」单独改一版**，板上确认即可。下一步直接做 **L1**。

检查板级 dts：

```dts
&i2c1 {
    clock-frequency = <100000>;
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_i2c1>;
    status = "okay";
};
```

`pinctrl_i2c1` 应含：

```dts
MX6UL_PAD_UART4_TX_DATA__I2C1_SCL  0x4001b8b0
MX6UL_PAD_UART4_RX_DATA__I2C1_SDA  0x4001b8b0
```

#### 内核三项配置各开什么、有何作用

| 配置 | 打开后内核里有什么 | 对 AP3216C 打通的作用 |
|------|-------------------|------------------------|
| **`CONFIG_I2C=y`** | I2C 核心：总线、适配器、client、`i2c_transfer`、驱动匹配框架 | 没有它，后面所有 I2C 驱动（含 AP3216C）都编不进来、也跑不起来 |
| **`CONFIG_I2C_IMX=y`** | i.MX I2C 控制器驱动（`i2c-imx`），按 dts `i2c@021a0000` 等节点创建 **`i2c-0/1/...` 适配器** | 把 SoC 的 I2C1 硬件变成 Linux 上的一条总线；`&i2c1 { status=okay }` 才真正 probe |
| **`CONFIG_I2C_CHARDEV=y`** | 字符设备层，出现 **`/dev/i2c-*`**，支持 `i2cdetect` / `i2cget` 等 | **不**替代 AP3216C 驱动；用来在绑驱动前**人工扫总线、读寄存器**排查 |

串起来看：

```text
CONFIG_I2C          →  框架（怎么传消息、怎么匹配驱动）
CONFIG_I2C_IMX      →  硬件控制器 → /sys/.../i2c-N 适配器
CONFIG_I2C_CHARDEV  →  /dev/i2c-N（给 i2cdetect 用）

再叠上：
  dts &i2c1 + ap3216c@1e
  CONFIG_LITEON_AP3216C  →  /dev/ap3216c（读 ALS/PS）
```

补充：

1. **`=y` 表示编进内核**（不是模块 `=m`），启动即有，无需 `insmod`。
2. **只有这三项还不够出 `/dev/ap3216c`**——那是 **L3** 的 `CONFIG_LITEON_AP3216C`；L0 保证的是：**I2C1 总线能起来，并能用 `i2cdetect` 做后续验证**。

**在哪执行：** 开发机核对源码/配置；板子核对运行态。

| 检查项 | 通过标准 | 失败常见原因 |
|--------|----------|--------------|
| `/dev/i2c-*` | 至少一个节点存在 | 缺 `I2C_CHARDEV`、I2C 控制器未 probe |
| sysfs 适配器 | `/sys/bus/i2c/devices/i2c-*` 存在 | `&i2c1 status` 非 okay、缺 `I2C_IMX` |
| dmesg | 无持续 i2c 控制器错误 | pinctrl / 时钟问题 |

**L0 通过标志：** 板上能列出 `/dev/i2c-*`，且 I2C 适配器已注册。  
**本层不要求** 一定能看到 `0x1e`（那是 L1+L2）；也不要求 `/dev/ap3216c`。  
**注意：** 同次启动里若出现 `fxls8471` / `mag3110` probe failed，**不否决 L0**（说明总线已起来、只是 EVK 遗留器件绑错）；交给 **L1** 改 dts。

### L1 — 改设备树（去掉冲突，挂上 AP3216C）

> L0 实测已证明 I2C1（`i2c-0`）可用；本层只改 dts：去掉 EVK 的 `fxls8471@1e` / 建议禁用 `mag3110@0e`，挂上 `ap3216c@1e`。  
> 改前失败现象见 **L0 实测日志⑤**（`fxls8471 ... 0-001e failed` 等）。

在 `projects/gengtao-bsp-0901/.../imx6ull-14x14-evk-gengtao0901.dts`（或你实际板级 dts）中：

1. **删除**（或 `status = "disabled"`）`fxls8471@1e` 整段；
2. **建议**将 `mag3110@0e` 设为 `status = "disabled"`（本板无该芯片时）；
3. **增加**：

```dts
ap3216c@1e {
    compatible = "LiteOn,ap3216c", "ap3216c";
    reg = <0x1e>;
};
```

**首轮不要强行加 interrupt**，减少 KEY0 / GPIO1_IO01 跳线干扰变量。

改完后重编并部署 **dtb**（驱动未进内核也可先做 L2 的 `i2cdetect`）。注意：实际启动文件名以 U-Boot 为准，本板当前为  
`imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dtb`。

#### L1 本板开发机实测（2026-09-03，dtb 反编译）

> cwd：`~/linux-imx6ull/tftpboot`；目标文件：`imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dtb`（已含 L1 改动）。

```text
$ dtc -I dtb -O dts imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dtb 2>/dev/null | grep -E 'fxls8471@1e|ap3216c@1e'
                                ap3216c@1e {

$ dtc -I dtb -O dts imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dtb 2>/dev/null | grep -A8 'ap3216c@1e'
                                ap3216c@1e {
                                        compatible = "LiteOn,ap3216c\0ap3216c";

```

**这条结果能说明什么：**

| 现象 | 说明 |
|------|------|
| 有 `ap3216c@1e` | L1 节点已编进 **将要 TFTP 的这份 dtb** |
| `compatible = "LiteOn,ap3216c\0ap3216c"` | 双字符串已写入（`\0` 是双兼容串在反编译里的正常显示） |
| `reg = <0x1e>` | 地址与硬件 / 文档一致 |
| **没有** `fxls8471@1e` | EVK 冲突节点已去掉，0x1E 不再被加速度计节点占用 |

**还不能说明什么（勿过度解读）：**

| 未覆盖项 | 原因 |

### L2 — 板上验证：I2C 能否看到 0x1E

> L2 是 **硬件 + I2C1 + 地址** 的门禁：驱动未就绪时，也应能扫到从设备。

#### 总线号如何确定（`i2cget -y <总线号>` 里的数字从哪来）

**不是**写死「原理图 I2C1 = 命令里的总线 0」，而是三条信息对齐后得到的：

| 层级 | 本板事实 | 说明 |
|------|----------|------|
| **硬件** | AP3216C 挂在 **I2C1**（SCL/SDA） | 原理图 / `04` 归纳 |
| **设备树** | `ap3216c@1e` 在 **`&i2c1`** 下；控制器节点为 **`i2c@021a0000`** | dtsi：`i2c1: i2c@021a0000`；I2C2 为 `i2c@021a4000` |
| **内核** | `i2c-imx` 按 **probe 顺序** 给适配器编号 | 本板先注册 I2C1 → **`/dev/i2c-0`**，再 I2C2 → **`/dev/i2c-1`** |

因此本板命令里的 **`<总线号> = 0`**，含义是：**操作 Linux 适配器 `i2c-0`，也就是硬件 I2C1（AP3216C 所在总线）**。

板上不确定时，用下面任一方式核对（不必死记「永远是 0」）：

```bash
ls /dev/i2c-*
ls /sys/class/i2c-adapter/

# 看 i2c-0 是否对应 SoC I2C1（期望路径含 i2c@021a0000）
readlink /sys/class/i2c-adapter/i2c-0/device/of_node

# 或：设备树里 ap3216c 挂在哪条控制器下
find /proc/device-tree -name 'ap3216c@1e'

# 保险：两条都扫一遍，哪条出现 1e 就用哪条总线号
for i in 0 1; do echo "=== i2c-$i ==="; i2cdetect -y $i; done
```

**L0 实测印证：** `/sys/bus/i2c/devices/` 曾有 `0-001e`（前缀 `0-` = 总线 0、地址 0x1e）；L1 后 `/proc/device-tree/.../i2c@021a0000/ap3216c@1e` 也落在同一控制器上。

确定总线号后，再扫地址 / 读寄存器：

```bash
ls /dev/i2c-*
i2cdetect -y 0    # 本板 AP3216C 在 i2c-0；若无响应再试 1
# 也可：for i in 0 1 2; do echo "=== i2c-$i ==="; i2cdetect -y $i; done
```

| 结果 | 含义 |
|------|------|
| `1e` | 总线上有从设备应答，**尚未**被内核驱动占用 |
| `UU` | 地址已被某驱动占用（L3 之后常见，也算通） |
| 整行 `--` | 无应答 → 供电 / pinctrl / 冲突 / 总线号错 |

可选（无驱动占用时）：

```bash
i2cget -y <总线号> 0x1e 0x00
# 本板 <总线号>=0；能读回一字节（复位后常见 0x00）即寄存器级通信通
```

#### L2 完成后验证

| 检查项 | 通过标准 | 失败常见原因 |
|--------|----------|--------------|
| `i2cdetect` | 对应总线上 **`1e` 或 `UU`** | 供电、I2C 脚、仍被错误驱动占死、扫错总线号 |
| （可选）`i2cget` | 可读 `0x00` | 地址错、器件未上电 |

**L2 通过标志：** `i2cdetect` 稳定看到 **0x1e / UU**。  
未通过 **不要** 急着改驱动逻辑；先查硬件与 dts。

**L2 结论：通过。** 可进入 **L3**（引入 `CONFIG_LITEON_AP3216C` 驱动；进驱动后同一地址常变为 `UU`）。

### L5 —（可选）接上 AP_INT

仅在需要中断唤醒/阈值阈值时再做：

```dts
ap3216c@1e {
    compatible = "LiteOn,ap3216c", "ap3216c";
    reg = <0x1e>;
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_ap3216c_int>;
    interrupt-parent = <&gpio1>;
    interrupts = <1 IRQ_TYPE_LEVEL_LOW>;   /* GPIO1_IO01；极性以手册为准再调 */
};

pinctrl_ap3216c_int: ap3216cintgrp {
    fsl,pins = <
        MX6UL_PAD_GPIO1_IO01__GPIO1_IO01  0x17059
    >;
};
```

注意：

- 出厂 `ap3216c.c` **当前未请求 IRQ**，只改 dts **不会自动用中断**；要改驱动 `request_threaded_irq` 等。
- `GPIO1_IO01` 可能与 **KEY0** 跳线共用，冲突时先断跳线或改 KEY 配置。

#### L5 完成后验证

> 仅当你已改驱动真正申请 IRQ 时，下表才有意义；**只改 dts 时**最多验证脚位配置正确。

```bash
# dts / procfs：中断属性是否进树
find /proc/device-tree -path '*ap3216c@1e*' | head
ls /proc/device-tree/.../ap3216c@1e/
# 期望有 interrupts、interrupt-parent（若已写）

# pinctrl：GPIO1_IO01 是否在 default 状态（需 debugfs，可选）
# cat /sys/kernel/debug/pinctrl/*/pinmux-pins | grep -i gpio1

# 驱动已 request_irq 后：
cat /proc/interrupts | grep -i ap3216
# 触发接近/光照阈值后，该行计数应增加
```

| 检查项 | 通过标准 | 说明 |
|--------|----------|------|
| dts 属性 | procfs 有 `interrupts` | 仅说明设备树写上了 |
| `/proc/interrupts` | 有对应 IRQ 且触发后计数增加 | **必须**驱动已 `request_irq` |
| 与 KEY0 | 按键与光感不互抢 | 跳线冲突时先断 KEY |

**L5 通过标志：** 中断路径在软件上真实生效（`/proc/interrupts` 计数变化），而非仅 dts 多了几行。

## 五、易踩坑（短表）

| 坑 | 说明 |
|----|------|
| 保留 `fxls8471@1e` | 与 AP3216C 同址，必冲突 |
| 只更 dtb 不更内核 | `/dev/ap3216c` 不会出现 |
| `compatible` 只写错一种 | 建议双写 `LiteOn,ap3216c` + `ap3216c` |
| 过早配 `AP_INT` | 与 KEY0/GPIO1_IO01 搅在一起，干扰首轮排查 |
| 把 MCU 驱动整文件塞进内核 | API 不同；直接用 IMX6 的 `drivers/char/ap3216c.c` |
| `i2cdetect` 总线号搞错 | **I2C1 ≠ 必然总线 0**；以 `of_node` / `0-001e` / 逐总线扫为准（见 L2「总线号如何确定」） |
| L2 未过就改驱动 | 先保证 `0x1e` 能扫到，再查 probe |

## 六、验收标准（打通即停）

按层勾选（与上文「完成后验证」一致）：

- [ ] **L0** 板上有 `/dev/i2c-*`，适配器已注册
- [ ] **L1** `/proc/device-tree` 有 `ap3216c@1e`，无冲突的 `fxls8471@1e`
- [ ] **L2** `i2cdetect` 可见 **0x1e**（或 `UU`）
- [ ] **L3** `CONFIG_LITEON_AP3216C=y`，新 zImage 已部署
- [ ] **L4** 存在 **`/dev/ap3216c`**；**ALS** 随光照变、**PS** 随靠近变
- [ ] **L5**（可选）IRQ 在 `/proc/interrupts` 中可计数

首轮打通：**L0～L4 全部勾上即可停**。

## 八、一句话

**ALPHA 底板 AP3216C = I2C1 地址 0x1E；删掉 EVK 的 fxls8471@1e，挂上 `ap3216c@1e`，从 `origin/IMX6` 引入 `CONFIG_LITEON_AP3216C` 驱动，用 `/dev/ap3216c` 读 ALS/PS；`AP_INT→GPIO1_IO01` 留作二期。每层做完先过该层验证再往下。**
