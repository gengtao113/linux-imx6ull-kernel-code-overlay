# 07 1024×600 屏幕打通：分析思路与落地顺序

> 文档编号：07  
> 日期：2026-09-01  
> 板卡：正点原子 ATK-MX6ULL（CORE V2.0 + ALPHA V2.4）  
> 屏幕：ATK-7RGBLCD 7 寸 **1024×600** RGB 并行屏  
> 目标：内核 `/dev/fb0` 为 1024×600，背光正常，能刷图显示  
> 相关原理图：`ATK-7RGBLCD(...).pdf` / `IMX6ULL_CORE_V2.0(...).pdf` / `IMX6ULL_ALPHA_V2.4(...).pdf`

---

## 一、先定结论（避免走弯路）

1. **不要写新 LCD 驱动**。i.MX6ULL 走 `LCDIF + mxsfb`，内核已有；板级工作是设备树时序与引脚。
2. **800×480 与 1024×600 硬件接口相同**（同一 40pin RGB 座），差别几乎全在 `display-timings`。
3. 当前真实阻塞点曾是：定制 dtb **文件名写了 1024-600，但 `lcdif` 仍是 EVK 默认 480×272**。
4. 正确路径：

   ```text
   应用 / 控制台刷屏
        ↑
   /dev/fb0（mxsfb）
        ↑
   LCDIF 控制器 + display-timings（分辨率/像素时钟/porch）
        ↑
   pinctrl：DATA0~23 + CLK/HSYNC/VSYNC/DE + 复位
        ↑
   PWM1 背光（BLT_PWM）
   ```

---

## 二、分析思路（为什么这样判断）

### 1. 从原理图抽出信号链

```text
SoC LCDIF ──核心板 LCD_* ──底板 RGB 座 ── ATK-7RGBLCD ── TFT
              │
              ├─ LCD_DATA0..23 → R/G/B
              ├─ LCD_PCLK / HSYNC / VSYNC / DE(ENABLE)
              ├─ BLT_PWM = GPIO1_IO08 / PWM1 → 背光
              └─ CT_RST  = SNVS_TAMPER9 / GPIO5_IO09 → 复位
                 （触摸 CT_INT / I2C 可后开，先打显示）
```

| 层级 | 作用 |
|------|------|
| 核心板 | LCDIF 管脚出脚；GPIO1_IO08=背光；SNVS_TAMPER9=复位 |
| 底板 ALPHA | 接到 RGB 座与背光/触摸相关网络 |
| ATK-7RGBLCD | 同一接口兼容 800×480 / 1024×600；背面丝印或上电读 R7/G7/B7 区分型号（裸机习惯） |

### 2. Linux 与裸机的差别

| 裸机 | Linux |
|------|--------|
| 读 `LCD_R7/G7/B7` 判屏 ID，再选参数 | 一般不读 ID，在 dts 写死时序 |
| 自己配 LCDIF 寄存器 | `mxsfb` + `display-timings` |

看清模组丝印是 1024×600 后，只维护一套 timing 即可。

### 3. 从现象分层

| 现象 | 优先查 |
|------|--------|
| 全黑 | 背光 PWM、供电、排线、`lcdif`/`pwm1` 是否 okay |
| 有背光无图 | 时序错误、fb 未创建、加载了错误 dtb |
| 花屏 / 错位 / 闪 | `clock-frequency`、porch、`pixelclk-active` |
| 分辨率仍是 480×272 或 800×480 | **实际加载的不是你以为的那份 dtb**，或 dts 未覆盖基线时序 |
| 颜色通道怪 | DATA↔RGB 映射（ATK 板一般不用改 pinctrl） |

### 4. 仓库里曾踩的坑

定制文件：

```text
imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dts
  └── #include imx6ull-14x14-evk-gengtao0901.dts
```

基线里 `&lcdif` 默认是 **480×272 / 9.2MHz**；板级文件若未覆盖 `&lcdif`，即使文件名写 1024-600，编出来的 dtb 仍是小屏时序。

反编译自检：

```bash
dtc -I dtb -O dts tftpboot/imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dtb \
  | grep -E 'hactive|vactive|clock-frequency'
# 期望：hactive=<0x400> (1024)  vactive=<0x258> (600)  clock=<0x30d4000> (51200000)
```

## 三、落地顺序（按这个做）

### 步骤 0：硬件确认

- [ ] 模组为 7 寸 **1024×600**（看背面丝印）
- [ ] RGB 排线方向、锁扣正确
- [ ] 底板供电正常

### 步骤 1：只改 overlay，不改内核树

文件：

```text
linux-kernel-overlay/projects/gengtao-bsp-0901/arch/arm/boot/dts/
  imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dts
```

在「板级定制区」把这块屏的 **display + timings 写在同一个 `&lcdif` 里**（基线只保留
pinctrl/status，不再带默认 480×272）：

```dts
&lcdif {
	display = <&display0>;

	display0: display {
		bits-per-pixel = <16>;
		bus-width = <24>;

		display-timings {
			native-mode = <&timing0>;
			timing0: timing0 {
				clock-frequency = <51200000>;
				hactive = <1024>;
				vactive = <600>;
				hfront-porch = <160>;
				hback-porch = <140>;
				hsync-len = <20>;
				vfront-porch = <12>;
				vback-porch = <20>;
				vsync-len = <3>;
				hsync-active = <0>;
				vsync-active = <0>;
				de-active = <1>;
				pixelclk-active = <0>;
			};
		};
	};
};
```

说明：

- `bus-width = <24>`：与原理图 24 线 RGB 一致  
- `bits-per-pixel = <16>`：先保证出图；稳定后再可试 24  
- 背光：基线已有 `pwm-backlight` + `pwm1`（GPIO1_IO08），一般不用再改

### 步骤 2：应用 overlay 并编译 dtb

```bash
cd ~/linux-imx6ull/linux-imx6ull-kernel-code/linux-kernel-overlay
./scripts/apply_overlay.sh gengtao-bsp-0901 --force

cd ..
source linux-kernel-overlay/scripts/common.sh
make ARCH=arm CROSS_COMPILE=$LINARO_CROSS \
  imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dtb -j$(nproc)
```

或一键：`./scripts/build_kernel.sh gengtao-bsp-0901`

### 步骤 3：部署到 TFTP

```bash
cp -f arch/arm/boot/dts/imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dtb \
  ~/linux-imx6ull/tftpboot/
# 或
./scripts/update_board.sh gengtao-bsp-0901 tftp
```

### 步骤 4：U-Boot 必须加载这份 dtb

出厂 `bootcmd` / `fdt_file` 可能被板级脚本覆盖，**写死文件名最稳**（见 03 / 06 文档）：

```bash
setenv bootcmd 'tftp 80800000 zImage; tftp 83000000 imx6ull-14x14-evk-emmc-gengtao0901-1024-600.dtb; bootz 80800000 - 83000000'
saveenv
boot
```

启动日志必须出现该文件名且 **`Loading: ... done`**，不能 File not found 后仍 boot（会用内存里旧 dtb）。

### 步骤 5：板上验证

```bash
ls /dev/fb0
cat /sys/class/graphics/fb0/virtual_size    # 期望 1024,600
cat /sys/class/graphics/fb0/bits_per_pixel

# 背光（busybox ash 重定向不要写 *，先 ls 再写全路径）
ls /sys/class/backlight/
echo 7 > /sys/class/backlight/backlight/brightness

# 粗刷测试（16bpp：1024*600*2 = 1228800 字节 ≈ count=1200）
dd if=/dev/urandom of=/dev/fb0 bs=1024 count=1200
```

### 步骤 6（可选）：触摸后开

显示稳定后再配 GT9xx（I2C + CT_INT + CT_RST）。分辨率变更后可能要改驱动最大坐标或做校准。

## 七、方法论小结

```text
第一层  原理图     确认 RGB/背光/复位已接到 LCDIF/PWM，不是缺驱动芯片协议
第二层  设备树     覆盖 display-timings；文件名不等于内容，务必反编译自检
第三层  启动链     bootcmd 写死 dtb 名，确认 TFTP Loading done
第四层  运行验证   fb0 分辨率 → 背光 → 刷屏；花屏再调时序
```

共性提醒：**老教程 / 多分辨率变体**下，最常见错误是「以为加载了大屏 dtb，实际仍是小屏时序」。先用 `dtc` 和 `virtual_size` 证伪，再调 porch。
