# 05 网卡打通：分析思路与落地顺序（自行实施）

> 文档编号：05  
> 日期：2026-09-01  
> 板卡：正点原子 ATK-MX6ULL（CORE + ALPHA V2.4）  
> PHY：底板 SR8201F × 2（RMII）  
> 目标：内核侧 eth0 可用 → NFS rootfs 登录  
> 实施人：自行按本文改 overlay / 编译 / 板载验证（本文只给思路与步骤，不含代改代码）

---

## 一、先定结论（避免走弯路）

1. **不要移植** `SR8201F/` 目录下的 MCU（GD32/STM32）驱动到 Linux。  
   那是裸机「配脚 → 复位 PHY → MDIO 自协商 → lwIP」示例。
2. Linux 上正确路径是：

   ```
   NFS / ping
       ↑
   内核协议栈
       ↑
   FEC MAC（内核已有）  ←→ RMII ←→ SR8201F PHY
       ↑
   设备树：pinctrl + phy-mode + phy 地址 + phy-reset-gpios
   ```

3. 当前阻塞点主要在 **设备树缺 PHY 硬件复位**，不是「缺一份 SR8201F.c」。  
   U-Boot 能 TFTP，说明硬件网口正常；内核靠 dts，没配复位就会 PHY 起不来。

---

## 二、分析思路（为什么这样判断）

### 1. 从现象分层

| 现象 | 含义 |
|------|------|
| U-Boot：`FEC1 ... done`，TFTP 成功 | 硬件链路、网线、PHY 芯片本身可用 |
| 内核：`fec eth0: registered` 但无 `attached PHY` | MAC 起来了，PHY 未正确挂上 |
| `IP-Config: Device 'eth0' not found` | 早期 IP 配置阶段网口不可用 → NFS 失败 |

结论：**问题在内核侧板级配置（dts/配置），不在 PCB 坏了。**

### 2. 从原理图抽出「必须写进 dts 的量」

底板 `IMX6UL_ALPHA_ENET.SchDoc` + 座子脚位：

| 项 | ENET1 | ENET2 |
|----|-------|-------|
| PHY | SR8201F（U14） | SR8201F（U15） |
| 模式 | RMII | RMII |
| 硬件地址 | **0x02** | **0x01** |
| 复位 | `ENET1_RST` = **GPIO5_IO07**（SNVS_TAMPER7） | `ENET2_RST` = **GPIO5_IO08**（SNVS_TAMPER8） |
| MDIO | 共用 GPIO1_IO06 / GPIO1_IO07 | 同左 |

手册补充：`PHYRSTB` 低有效；标准 Clause22 寄存器（BCR/BSR）；PHY ID 偏 `0x001C` 系，**不是** SMSC LAN8720 的 `0x0007`。

### 3. 从 MCU 驱动只吸收「语义」，不吸收「代码形态」

| MCU 示例在做什么 | Linux 对应谁做 |
|------------------|----------------|
| 配 RMII 脚 | dts `pinctrl_enet*` |
| `PHY_ADDRESS` | dts `reg = <1>` / `<2>` |
| 拉 `PHYRSTB` | `phy-reset-gpios` + reset 的 pinctrl |
| MDIO 读写 BCR/BSR、自协商 | phylib（通用 PHY） |
| 再开 MAC / lwIP | fec 驱动 + 内核协议栈 |

对照 GD 示例：`PHY_TYPE=SR8201F`、`PHY_ADDRESS`、软件复位 `BCR bit15` —— 证明用标准 MDIO 即可，无需私有内核驱动。

### 4. 从出厂实现验证路径（IMX6 分支）

```bash
git -C ~/linux-imx6ull-code/linux-imx6ull-kernel-code \
  show origin/IMX6:arch/arm/boot/dts/imx6ull-14x14-evk.dts
```

要点：

- `phy-mode = "rmii"`
- `phy-reset-gpios = <&gpio5 7/8 GPIO_ACTIVE_LOW>`
- `phy-reset-duration = <200>`
- `pinctrl` 含 `pinctrl_fec*_reset`
- PHY 节点：`compatible = "ethernet-phy-ieee802.3-c22"`（**通用 PHY**，不是强绑 SMSC）

### 5. 对照你当前 overlay 的缺口

文件：`projects/gengtao-bsp-0901/arch/arm/boot/dts/imx6ull-14x14-evk-gengtao0901.dts`

已有：`rmii`、`phy-handle`、mdio 下 `@2` / `@1`。  
**缺少：** `phy-reset-gpios`、`pinctrl_fec1_reset` / `pinctrl_fec2_reset` 及其引用。

这与「U-Boot 通、内核 NFS 不通」完全吻合。

### 阶段 1：只改设备树（优先，改动面最小）

**改哪里（只动 overlay，勿直接改内核树）：**

`linux-kernel-overlay/projects/gengtao-bsp-0901/arch/arm/boot/dts/imx6ull-14x14-evk-gengtao0901.dts`

**做什么：**

1. `&fec1` / `&fec2` 增加：
   - `phy-reset-gpios`
   - `phy-reset-duration = <200>`
   - `pinctrl-0` 追加 `&pinctrl_fec*_reset`
2. 在 `iomuxc_snvs` 里增加 `pinctrl_fec1_reset` / `pinctrl_fec2_reset`（脚位见上表；脚码对照 IMX6 同名节点）
3. 保持 mdio：
   - `ethernet-phy@2` → ENET1，`reg = <2>`，`compatible = "ethernet-phy-ieee802.3-c22"`
   - `ethernet-phy@1` → ENET2，`reg = <1>`，同上
4. **顺带必做（脚位冲突）：** 将 EVK 的 `spi4`（gpio-spi / 74HC595）设为 `status = "disabled"`。  
   ALPHA 上 `GPIO5_IO07/08` 是 PHY 复位，不能再给 spi4 用；IMX6 出厂 dts 同样关闭 spi4。

**建议对照命令：**

```bash
git -C ~/linux-imx6ull-code/linux-imx6ull-kernel-code \
  show origin/IMX6:arch/arm/boot/dts/imx6ull-14x14-evk.dts | \
  sed -n '/&fec1/,/pinctrl_fec2_reset/,+8p'
```

**本阶段成功标准（改完编译部署后）：**

```

且不再出现：
```

### 阶段 4：若仍失败，再按序排查（2026-09-01 实测结论已写入）

#### 4.0 先读懂日志（易误判）

若同时出现：

```
fec 20b4000.ethernet eth0: registered PHC device 0
fec 2188000.ethernet eth1: registered PHC device 1
...
IP-Config: Failed to open eth0
IP-Config: Device `eth0' not found
```

含义是：

| 日志 | 真实含义 |
|------|----------|
| `registered PHC` | netdev **已注册**，名字 eth0/eth1 存在 |
| `Failed to open eth0` | 对 eth0 做 `IFF_UP` **失败**（通常 `fec_enet_open` → `of_phy_connect` 失败） |
| `Device eth0 not found` | **误导性二次报错**：指定了 `ip=...::eth0:...` 但没有成功 UP 的设备，ipconfig 就打印这句 |

**没有** `Freescale FEC PHY driver [Generic PHY]` / `attached PHY` → PHY 未挂上。

#### 4.1 eth0 不一定是你插网线的那路

| 名字 | SoC 地址 | dts 标签 | U-Boot |
|------|----------|----------|--------|
| **eth0** | `020b4000` | **fec2 / ENET2** | 通常不是 U-Boot 默认口 |
| **eth1** | `02188000` | **fec1 / ENET1** | U-Boot 日志里的 **FEC1**（TFTP 用的就是它） |

网线插在「第一网口 / U-Boot 能 TFTP 的口」时，内核侧对应更可能是 **eth1**，不是 eth0。

#### 4.2 dts 复位已生效后仍失败 → 需要 IMX6 的 fec 板级补丁

对照 `git diff master-gengtao-0901 origin/IMX6 -- drivers/net/ethernet/freescale/fec_main.c`：

1. **复位后再等 150ms**（注释写明给 SR8201F）
2. **probe 里强写 ENET TX_CLK pad 为 0x14**
3. dts 里 `ENET*_TX_CLK` pad 对齐 IMX6：`0x4001B009`

**已落地（overlay，2026-09-01）：**

| 项 | 位置 |
|----|------|
| fec 补丁 | `projects/gengtao-bsp-0901/drivers/net/ethernet/freescale/fec_main.c` |
| baseline 快照 | `.baseline/drivers/net/ethernet/freescale/fec_main.c` |
| MANIFEST | `M drivers/net/ethernet/freescale/fec_main.c` |
| TX_CLK pad | `imx6ull-14x14-evk-gengtao0901.dts` → `0x4001B009` |

验证：`./scripts/build_kernel.sh gengtao-bsp-0901`（必须重编 **zImage**，不只是 dtb）→ `update_board.sh ... tftp` → 看是否出现 `Freescale FEC PHY driver`；若仍 NFS 失败，cmdline 试 `eth1`（对应 U-Boot FEC1）。

#### 4.3 排查优先级（更新）

1. 确认新 dtb 已加载（文件名 + 体积变大，如 36093→36404）
2. 确认日志是 `Failed to open`（PHY 挂载失败），不是真的没设备
3. 把 IMX6 的 `fec_main.c` 两处补丁 + TX_CLK pad 值纳入 overlay，重编内核（不只是 dtb）
4. 部署后若仍 NFS 失败，U-Boot 临时改 cmdline 试 **`eth1`**（对齐 U-Boot FEC1）
5. 仍失败再查 MDIO/PHY ID；**不要**先抄 MCU 驱动架构
6. `smsc.c` 的 IMX6 改动偏 SMSC 专用且出厂 dts 用的是 generic PHY，**次优先**

## 六、一句话

**落地：** 先改 `gengtao0901.dts` 对齐 IMX6/原理图 → 编译部署 → 看 `attached PHY` 与 NFS → 不通再按阶段 4 排查 → 通了再 git 里程碑。
