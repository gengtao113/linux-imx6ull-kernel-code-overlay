# 12 AP3216C 光感打通-问题复盘

> 文档编号：12  
> 日期：2026-09-03  
> 板卡：正点原子 ATK-MX6ULL（CORE V2.0 + ALPHA V2.4）  
> 器件：底板 **U9 AP3216C**（ALS 环境光 + PS 接近 + IR）  
> 关联：`04`（原理图）、`11`（分析与落地顺序）、`origin/IMX6`（出厂驱动）  
> 结果：✅ `/dev/ap3216c`；`i2cdetect` **0x1e=`UU`**；sysfs `als`/`ps`/`ir` 可读（首轮打通；L5 中断未做）

---

## 一、目标与软件链

```text
用户态：cat sysfs / ioctl
      ↑
/dev/ap3216c（misc）+ als/ps/ir
      ↑
drivers/char/ap3216c.c（CONFIG_LITEON_AP3216C）
      ↑
dts：&i2c1 → ap3216c@1e（reg=0x1e）
      ↑
硬件：I2C1_SCL/SDA；VCC_3V3；（INT→GPIO1_IO01 二期）
```

目标：在 NXP 纯净基线 + overlay（`gengtao-bsp-0901`）下，去掉 EVK 遗留冲突节点，引入正点出厂驱动，板上可读 ALS/PS。

---

## 二、现象时间线

| 阶段 | 关键现象 | 结论 |
|------|----------|------|
| A. 起点 | dts 仍是 EVK：`fxls8471@1e` + `mag3110@0e`；无 AP3216C 驱动 | 地址 0x1E 被错误器件占用；无 `/dev/ap3216c` |
| B. L0 | `/dev/i2c-0`/`i2c-1` 已有；`IMX I2C adapter registered` | I2C 子系统 OK；**不必**为开 I2C1 再改一版 |
| C. L0 干扰日志 | `fxls8471: probe of 0-001e failed`；`mag3110 ... chip ID` 失败 | **属 L1 冲突**，不判 L0 失败 |
| D. L1 | 删 `fxls8471@1e`，挂 `ap3216c@1e`，禁 `mag3110`；procfs 见节点 | dts 冲突清除；尚无驱动日志属正常 |
| E. L2 | `i2cdetect -y 0` 见 **`1e`**（非 UU）；`i2cget … 0x00` → `0x00` | 硬件 + 总线通；驱动未绑 |
| F. L3 | overlay 引入驱动 + `CONFIG_LITEON_AP3216C=y`；新 zImage | 开发机 `nm vmlinux` 有 `ap3216c_probe` |
| G. 板上误判点 | `dmesg \| grep ap3216` **为空**；却已有 `/dev/ap3216c` | 成功路径**不打日志**；以节点为准 |
| H. L4 | `0x1e`→**`UU`**；sysfs 有 als/ps/ir；`als` 可读（如 `10`） | ✅ 驱动占用地址且能读数 |

## 三、根因与修复

### 问题 1：EVK 遗留 `fxls8471@1e` 与 AP3216C 同址

**根因**

```text
原理图：ALPHA U9 AP3216C @ I2C1 / 0x1E
EVK dts：fxls8471@1e 也占 0x1E
→ 错误驱动 probe 失败；即使加 ap3216c 也会冲突
```

L0 典型失败日志（改 dts 前）：

```text
fxls8471: probe of 0-001e failed with error -22
mag3110 0-000e: read chip ID 0xfffffffb is not equal to 0xc4!
```

**修复**（`imx6ull-14x14-evk-gengtao0901.dts` `&i2c1`）：

```dts
mag3110@0e {
	compatible = "fsl,mag3110";
	reg = <0x0e>;
	status = "disabled";
};

ap3216c@1e {
	compatible = "LiteOn,ap3216c", "ap3216c";
	reg = <0x1e>;
};
```

- 删掉整个 `fxls8471@1e`
- `compatible` **双写**：`of_match` 用 `LiteOn,ap3216c`，id_table 用 `ap3216c`

### 问题 2：驱动不在纯净基线，只改 dtb 不够

**根因**：`master-gengtao-0901` 无 `ap3216c.c`；出厂实现在 **`origin/IMX6`**。

**修复**：抽进 overlay 并打开配置：

| overlay 路径 | 作用 |
|--------------|------|
| `common/drivers/char/ap3216c.c` | 驱动 |
| `common/include/linux/ap3216c.h` | ioctl |
| `common/drivers/char/Kconfig` / `Makefile` | `LITEON_AP3216C` |
| `projects/.../imx_v7_defconfig` | `CONFIG_LITEON_AP3216C=y` |

必须 **`build_kernel.sh` → 更新 zImage**（+ dtb）。只换 dtb 不会出现 `/dev/ap3216c`。

### 问题 3：Linux 总线号 ≠ 原理图「I2C1」

**根因**：适配器号按 probe 顺序分配，不是硬件编号字面。

**本板对照**：

| 硬件 | 控制器 | Linux |
|------|--------|-------|
| I2C1（AP3216C） | `i2c@021a0000` | **`i2c-0`** |
| I2C2 | `i2c@021a4000` | `i2c-1` |

故 `i2cdetect -y 0` / `i2cget -y 0 …`。不确定时：

```bash
readlink /sys/class/i2c-adapter/i2c-0/device/of_node
# 期望含 i2c@021a0000
```

### 问题 4：用 `dmesg | grep ap3216` 当成功判据 → 误判

**根因**：出厂 `ap3216c_probe` 成功时**不 printk**；仅失败打：

```text
ap3216c init failed
```

**正确判据**：

```bash
ls -l /dev/ap3216c          # 有节点 = probe + init + misc_register 成功
i2cdetect -y 0              # 0x1e 为 UU
cat /sys/devices/virtual/misc/ap3216c/als
```

## 四、易误判项（短表）

| 现象 | 真实含义 |
|------|----------|
| `dmesg` 无 `ap3216` | **成功常见**；勿当失败 |
| `i2cdetect` 显示 **`UU`** | 驱动已占用该地址（Used），**不是错误** |
| L2 时显示 **`1e`** | 有应答、尚未绑驱动，也属通 |
| 板上跑 `arm-linux-gnueabihf-nm` | 工具在**开发机**；板子无此命令 |
| Kconfig 搜不到 `CONFIG_LITEON_AP3216C` | Kconfig 写的是 `config LITEON_AP3216C`（无前缀） |
| 同总线还有 `1a` | 另有从设备；不挡光感；勿与 I2C2 的 wm8960@1a 混为一谈 |
| 过早配 `AP_INT`/GPIO1_IO01 | 易与 KEY0 跳线搅在一起；出厂驱动**不用中断** |

## 五、最终验收（板上）

```bash
ls -l /dev/ap3216c
# crw-rw----  … 10, 63 … /dev/ap3216c

i2cdetect -y 0
# 0x1e 处为 UU

ls /sys/devices/virtual/misc/ap3216c/
# als  ir  ps  …

cat /sys/devices/virtual/misc/ap3216c/als
cat /sys/devices/virtual/misc/ap3216c/ps
cat /sys/devices/virtual/misc/ap3216c/ir
```

功能对照（遮光/靠近后数值应变化；交互脚本见文档 **11** L4）：

| 实验 | 期望 |
|------|------|
| 遮光 ↔ 照光 | **ALS** 明显变化 |
| 手指靠近 ↔ 远离 | **PS** 明显变化 |

本板已确认节点 + `UU` + sysfs 可读；遮光/靠近数值变化按 **11** 脚本补记即可完全勾选 L4。

## 八、经验沉淀（可复用到其它 I2C 器件）

1. **先原理图对地址与总线**，再查 EVK dts 是否同址冲突。  
2. **先 `i2cdetect`/`i2cget`（无驱动）再绑驱动**，分层不堆问题。  
3. **板厂驱动优先抄 `origin/IMX6`**，裸机例程只懂寄存器。  
4. **成功日志缺失时，以 `/dev` + `UU` + sysfs 为准。**  
5. **改驱动必须换 zImage**；只换 dtb 只解决节点描述。

---

## 九、一句话

**删掉 EVK 的 `fxls8471@1e`，挂上 `ap3216c@1e`，从 `origin/IMX6` 引入 `CONFIG_LITEON_AP3216C`；本板 I2C1=`i2c-0`；以 `/dev/ap3216c` + `UU` + 可读 als/ps 判打通，勿依赖成功 dmesg；中断留二期。**
